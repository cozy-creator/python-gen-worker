# pgw#966 — every skip this suite takes, and what answers it.
#
# `scripts/lint_skip_census.py` reads this against the skips a run ACTUALLY took
# (`pytest --skip-census-out=...`, wired by the repo-root conftest.py). Two
# rules: an observed skip missing from this file fails the build; in `--ci` mode
# an observed `CI-MUST-RUN` key fails the build. A skipped row and a passing row
# look identical in a green log — this file is what makes the difference
# readable, and the guard is what makes it enforceable.
#
# WHY THIS EXISTS. pgw#858's container row skipped on `ubuntu-latest` from the
# day it landed, on a by-name skip for exit 127, and read as coverage in every
# green run since. It measures a uid boundary — the one row proving tenant code
# cannot read the RunPod account-authority key out of PID 1 — and it had only
# ever executed on developer boxes. That is how the pgw#956 flake reached `dev`.
#
# FORMAT: `<DISPOSITION> <file>|<normalized reason>`, one per line. The key is
# printed verbatim in the guard's failure message; paste it.
#
#   CI-MUST-RUN  Expected to EXECUTE on ubuntu-latest. Observing it skipped
#                there is a build failure, not a note.
#   CI-SKIPPED   Legitimately un-runnable on the runner. Says where the property
#                IS measured, or that it is unverified.
#   LOCAL-ONLY   Opt-in by design everywhere, CI included (benchmarks, rows keyed
#                to a banked local artifact, explicit env switches).
#   STAGED       Blocked on work that has not landed; names the issue.
#
# Do NOT pre-classify a skip you have not seen. An unobserved key that turns out
# to be spelled differently is a line that can never match, and the guard firing
# once with the exact line to paste costs less than a wrong guess.
#
# ─── WHAT IS NOT MEASURED ANYWHERE, STATED PLAINLY ────────────────────────────
#
# Nothing in this repository is tested on a GPU by any automated lane. There is
# no CUDA device on `ubuntu-latest`, and GPU CI runners are out of scope
# (pgw#953, parked in the tracker's future.md). Every `needs CUDA` /
# `needs a CUDA device` / `triton unavailable` row below is therefore not
# "covered by the nightly lane" — it is UNVERIFIED except by hand on a pod, and
# a green CI is no evidence about any of it. Saying so here is the point; before
# pgw#966 a reader had no way to find it out short of auditing 63 skip sites.
#
# ─── THIRD PARTIES ────────────────────────────────────────────────────────────
#
# A check that can go red because someone else's rate limiter had a bad minute
# is not a check — the same property a silently-skipped row breaks, from the
# other side. The suite reaches exactly three third parties, all of which now
# degrade to a counted skip below rather than to a red:
#
#   github.com  the pinned llama-server tarball (ci.yml, continue-on-error).
#   Docker Hub  `ubuntu:24.04` for the pgw#858 root parent (exit 125 -> skip).
#   PyPI        `uv build` + `uv pip install` in the pgw#740 wheel row — the
#               same PyPI `uv sync --locked` already required in step 5.
#
# huggingface.co used to be a fourth: `test_llama_runtime.py` ran an
# `hf_hub_download` on every CI run, and PR #483's tests job went red on a `429`.
# The model is now vendored (`tests/testdata/stories260K.gguf`, 1,185,376 bytes,
# digest-checked at fixture time). There is no fourth any more.
