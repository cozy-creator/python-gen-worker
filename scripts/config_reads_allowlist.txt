# pgw#929 + pgw#931 — the env census, classified. Enforced by scripts/lint_config_reads.py.
#
# Ruling §1.18: exactly one component per process reads the environment
# (`gen_worker.config`). Every OTHER `os.environ` / `os.getenv` access in
# `src/gen_worker` needs a line here or CI fails.
#
# FORMAT:  <path>:<line>  <CLASSIFICATION>  <reason>
#
#   VIOLATION   a config value read behind the pipeline. A DEFECT, listed only
#               so the gate can be green while it is burned down. Every line
#               must name what blocks it. Adding one needs a reason a reviewer
#               will accept, not just a passing build.
#   BOOTSTRAP   read before config can exist. Must stay a named, tiny set — if
#               it grows, the boundary is drawn in the wrong place.
#   IPC         a parent handing a value to a child across an exec boundary.
#               §1.17's verdict is that these belong on argv; §1.18's addition
#               is that a value ORIGINATING in config must reach the child as
#               config, never as an env the parent re-exported.
#   LIBRARY     the target library reads env at import and exposes no other
#               API (torch/inductor/triton/NCCL). Legitimate mechanism; the
#               VALUE should still come from a Settings-derived builder.
#   STANDALONE  a CLI/convert path that loads no app config.
#   TRIPWIRE    a guard whose entire purpose is to fire on a misconfiguration.
#               It carries no behaviour of its own and is correctly loud.
#
# Baselined the way th#1383 baselined the Go gate: seeded with today's accepted
# sites so it is green on arrival, then burned down. A gate that fails on day
# one gets switched off.
#
# SCOREBOARD at the pgw#929/930/931 landing: 100 sites (106 before; six raw
# config reads were deleted outright, five of them `or os.environ.get(...)`
# clauses sitting next to the Settings field for the SAME fact).
#
# The count went UP against the issue's 103 because the gate catches a shape the
# issue's grep could not: `os.environ` bound as a VALUE (`dict(os.environ)`,
# `source = os.environ`). Eight such sites, and they are the widest reads in the
# tree - three of them are the child-env denylist.
#   VIOLATION 17 | BOOTSTRAP 6 | IPC 21 | LIBRARY 30 | STANDALONE 18 | TRIPWIRE 8

# NOTE — the seven "kill switches" pgw#929 lists for deletion. FIVE can go once
# their unconditional path has a named observable; TWO CANNOT, and saying so is
# part of the finding.
#
# Measured on the standing hub 2026-08-03: `release_env_declarations` and
# `endpoint_env_entries` carry exactly two GEN_WORKER_* names fleet-wide,
# GEN_WORKER_PREFER_AOT (19 declarations, 2 live entries) and
# GEN_WORKER_AOT_RUN_IMPL_SPLIT_OFF (5 declarations, 1 live entry). None of the
# seven kill switches is declared anywhere.
#
# Zero declarations is NOT the same fact as safe-to-delete, and the direction of
# the default decides which:
#
#   DEFAULT-ON  (HOST_MOVE_GUARD, MINT_IN_PROCESS, EAGER_FIRST_BOOT, BG_YIELD,
#               AOT_WRAPPER_SPLIT_OFF) — deleting the env makes the CURRENT
#               PRODUCTION BEHAVIOUR unconditional. Safe. Blocked only on the
#               replacement observable pgw#929 requires, plus the fact that the
#               tests set BG_YIELD=0 / EAGER_FIRST_BOOT=0 as red-verification
#               seams: those need a real parameter, not an env, before the
#               switch goes.
#
#   DEFAULT-OFF (AOT_EXPORT_PARALLEL, AOT_EXPORT_REUSE) — deleting the env would
#               make an UNPROVEN path unconditional. Both ship dark by their own
#               docstrings ("turning it on needs the export-phase VRAM
#               measurement first"; "ships dark until a real family's mint has
#               run the gate on a pod"), and neither enable path has ever run in
#               production. Making them unconditional is not a deletion, it is a
#               launch. pgw#929's "delete seven kill switches" is WRONG for
#               these two.
#
#               If they encode a decision nobody makes — which the measurement
#               supports — the §2.2 answer is to delete the FEATURES, ~500 lines
#               of dark code. That is a call for Paul, not a side effect of an
#               env census, so it is recorded here rather than taken.
