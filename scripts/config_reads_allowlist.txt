# pgw#929 + pgw#931 — the env census, classified. Enforced by scripts/lint_config_reads.py.
#
# Ruling §1.18: exactly one component per process reads the environment
# (`gen_worker.config`). Every OTHER `os.environ` / `os.getenv` access in
# `src/gen_worker` needs a line here or CI fails.
#
# FORMAT:  <path>::<ENV_NAME>  <CLASSIFICATION>  <reason>
#
# Keyed on the VARIABLE, never on a line number. The first cut of this gate used
# `path:line` and went red on `dev` within the hour: two sibling PRs merged
# alongside it and shifted lines in four files nobody in that change had touched.
# A line number is a fact OTHER PEOPLE change independently, so pinning an
# allowlist to one makes it a second carrier that goes stale silently — §4.22,
# and exactly the defect class this gate exists to police. `::<unresolved>` is
# for a bare `os.environ` binding; `::$NAME` for a constant imported from a
# sibling module, where the identifier is the stable key.
#
#   VIOLATION   a config value read behind the pipeline. A DEFECT, listed only
#               so the gate can be green while it is burned down. Every line
#               must name what blocks it. Adding one needs a reason a reviewer
#               will accept, not just a passing build.
#   BOOTSTRAP   read before config can exist. Must stay a named, tiny set — if
#               it grows, the boundary is drawn in the wrong place.
#   IPC         a parent handing a value to a child across an exec boundary.
#               §1.17's verdict is that these belong on argv; §1.18's addition
#               is that a value ORIGINATING in config must reach the child as
#               config, never as an env the parent re-exported.
#   LIBRARY     the target library reads env at import and exposes no other
#               API (torch/inductor/triton/NCCL). Legitimate mechanism; the
#               VALUE should still come from a Settings-derived builder.
#   STANDALONE  a CLI/convert path that loads no app config.
#   TRIPWIRE    a guard whose entire purpose is to fire on a misconfiguration.
#               It carries no behaviour of its own and is correctly loud.
#
# Baselined the way th#1383 baselined the Go gate: seeded with today's accepted
# sites so it is green on arrival, then burned down. A gate that fails on day
# one gets switched off.
#
# SCOREBOARD at the pgw#929/930/931 landing: 79 (file, variable) pairs.
#   VIOLATION 14 | BOOTSTRAP 6 | IPC 18 | LIBRARY 17 | STANDALONE 18 | TRIPWIRE 6
#
# The unit is one FILE reading one VARIABLE, which is the unit a classification
# actually belongs to. It is smaller than the raw access count (106 lines before
# this work, 100 after) because two lines in one file reading the same variable
# are one decision, not two.

# NOTE — the BEHAVIOUR axis (pgw#995), and the kill-switch verdicts.
#
# The six classifications above answer WHERE a read happens relative to the
# config pipeline. They do NOT answer whether the read SELECTS BEHAVIOUR, and
# those are orthogonal. `GEN_WORKER_PREFER_AOT` was a behaviour switch that
# silently disarmed on a release rebuild and took the whole AOT path dark for
# three pod attempts; nothing in a WHERE-shaped classification could have
# flagged it. Evidence the axis was missing rather than implicit: this file used
# to classify `GEN_WORKER_AOT_EXPORT_PARALLEL` and `_REUSE` as LIBRARY (torch has
# never heard of either name — they are first-party feature gates) and
# `GEN_WORKER_BG_YIELD` / `_EAGER_FIRST_BOOT` / `_MINT_IN_PROCESS` as STANDALONE
# ("a CLI that loads no app config") while all three were read from executor.py
# on the serving hot path of every production pod.
#
# So: `scripts/lint_config_reads.py` now also asserts the behaviour axis, and
# Paul's rule is enforced rather than restated — env carries CONFIG, SECRETS and
# TUNING VALUES. A branch selector needs typed config, a loud typed observable,
# and a named threat.
#
# THE DIRECTION OF THE DEFAULT DECIDES WHETHER A GATE CAN BE DELETED:
#
#   DEFAULT-ON  — deleting the env makes the CURRENT PRODUCTION BEHAVIOUR
#               unconditional, so no pod changes behaviour. Safe.
#   DEFAULT-OFF — deleting the env makes an UNPROVEN path unconditional. That
#               is not a deletion, it is a LAUNCH. pgw#929's "delete seven kill
#               switches" is WRONG for these, and saying so is the finding.
#
# A declaration count is worth knowing, but it does NOT gate retiring a NAME.
# pgw#1305 measured the mechanism: an unknown owned-namespace name arriving in
# the PROCESS environment is reported by `unrecognised_owned_env`, never
# refused, and process env is the only way the hub delivers one. What a count
# would gate is deleting a READ SITE whose default flips behaviour — that is
# the DEFAULT-OFF case above, and it is a launch, not a deletion.
#
# VERDICTS (declaration counts measured on the standing hub 2026-08-03):
#
#   DELETED by pgw#1010 — with the SHAPE it selected, not merely the switch:
#     GEN_WORKER_MINT_IN_PROCESS        in-process minting existed only to pack
#             a dynamo cell; a dynamo miss now serves JIT intake and packs
#             nothing, so "mint in this process" is not a reachable state. The
#             ten test sites pgw#995 was blocked on went with the shape.
#
#   DELETED by pgw#995 — default-ON, zero declarations:
#     GEN_WORKER_BG_YIELD               pgw#677 bg-yield is now unconditional
#     GEN_WORKER_EAGER_FIRST_BOOT       pgw#671 eager-first is now unconditional
#     GEN_WORKER_AOT_WRAPPER_SPLIT_OFF  v1 ctor-split is now unconditional
#
#   READ SITE AND NAME BOTH GONE — pgw#1270 then pgw#1305:
#     GEN_WORKER_AOT_RUN_IMPL_SPLIT_OFF `aot_wrapper_split.py` read it, and TCG
#     GEN_WORKER_AOT_HOST_COMPILE_JOBS  owns the run_impl split now, so the read
#     GEN_WORKER_MINT_RESUME_DIR        sites died with their modules and this
#     GEN_WORKER_MINT_RESUME_MAX_BYTES  file's rows went with them.
#             pgw#1270 then held the NAMES in `_OWNED_NON_SETTINGS` pending "a
#             fresh measured count of zero", on the stated hazard that dropping
#             a declared name makes a deployed pod fail config load.
#             THAT HAZARD DOES NOT EXIST, and pgw#1305 measured the mechanism
#             instead of the count. `UnknownSettingError` is raised only from
#             `_normalize_key(strict=True)`, whose only callers are the FILE
#             sources — `.env`, yaml, `/run/secrets`. The process environment
#             never reaches it: `_load_env` indexes `_ENV_TO_FIELD` and never
#             asks about a name it does not know, and `unrecognised_owned_env`
#             REPORTS owned-namespace residue at boot rather than refusing it,
#             for exactly the reason stated in its docstring. Tensorhub delivers
#             a release's declared env only as container process env (RunPod
#             `CreatePodRequest.Env`, Vast `CreateInstanceRequest.Env`, k8s
#             inline `corev1.EnvVar`, local `docker run -e`); it writes no
#             `.env`, yaml or `/run/secrets` file into a worker container.
#             So a pod still declaring one of these boots green and NAMES the
#             name at boot — which is what retiring a name is supposed to do.
#             The census was never the gate. Fenced by
#             tests/test_retired_env_names_pgw1305.py.
#
#   NOT DELETED, and each for a stated reason:
#     GEN_WORKER_HOST_MOVE_GUARD        ruled exception: safety guard, on by
#             default, named threat, documented. Do not touch.
#     GEN_WORKER_PROBE / _PUBLISH_ARMED security boundary; deliberately NOT a
#             Settings field so tenant-adjacent code cannot reach it.
#     PODGUARD_STATE                    producer is outside this process.
