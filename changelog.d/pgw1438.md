- **Every worker reported an empty `gpu_sm`, and refused every request for it.** `probe_hardware`
  moved out of `gen_worker/lifecycle.py` into `procsplit/measure.py` (pgw#1373), where its
  `from .models.hub_policy import ...` stopped meaning `gen_worker.models` and started meaning
  `gen_worker.procsplit.models`, which does not exist — and the `except Exception: pass` around it
  ate the `ModuleNotFoundError`. So `gpu_sm`, `torch_version`, `cuda_version` and `installed_libs`
  were empty on every worker in the fleet, while pgw#984 derives a `min_sm` on every v2 release:
  those hosts registered `class=gpu`, looked healthy, and refused everything sent to them with
  `gpu_capability_incompatible`. This is pgw#1436/pgw#1417's root cause — the capability was never
  computed, not merely unreported.

- **No v2 endpoint could save any output.** The v2 worker rewrite carried `input_payload` and
  `models` into a dispatch and nothing else, so `RunJob.capability_token` reached no
  `RequestContext` and `ctx.save_bytes` / `save_image` / `save_file` / `save_audio` / `save_video`
  all raised `worker_capability_token is required for file operations` — the output of every media
  endpoint. `ServeLoop.invoke` now takes a per-request `context=`, filled from the RunJob (org,
  invoker, token, inline-output preference) with `file_base_url` off the HelloAck. It cannot ride
  the loop's construction-time `context_kwargs`: a capability token is minted per request and
  expires.

- **`python -m gen_worker.serve` starts again**, and `component_load_dtypes` stops raising. The
  adopt-only entry still imported `worker_main`, renamed back to `entrypoint` in pgw#1373 because
  the module name is the wire contract every synthesized Dockerfile's ENTRYPOINT writes;
  `models/loading.py` still imported the deleted `api/tree.py` for the rule that loads the Wan and
  H3 VAEs wider than the composition dtype. That rule's half (`component_classes`) now lives in
  `families/facts.py`, beside the facts table it keys into.

- **New guard: every in-repo import in `src/` must name a module that exists.** All four defects
  above were invisible to grep — two are relative imports whose meaning depends on the importing
  module's package, which is exactly what broke both times a function moved.
  `tests/test_in_repo_imports_resolve.py` resolves them the way Python does.
