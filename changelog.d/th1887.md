- **th#1887: two behaviour-switch environment variables are deleted.** Paul:
  *"get rid of these envs please, unless you really need them. I hate envs like
  this."* `GEN_WORKER_VIDEO_ENCODER` is gone — the NVENC probe was always the
  real decision, since `x264` only SKIPPED the probe and `nvenc` already fell
  back to x264 when it failed, so the switch's only power was to make a pod
  encode on CPU while its NVENC ASIC sat idle and never report the gap.
  `GEN_WORKER_SVDQ_ENGINE` is gone — a PROCESS-wide pin over a PER-ARTIFACT
  decision, so one incident's pin outlived the incident and silently served
  every later artifact on the wrong engine; the typed per-call `override=`
  argument survives and cannot leak into the next load. Both deletions are
  proved by tests that assert the env is INERT: exporting the value that used
  to win now changes nothing, checked against a forced-positive NVENC probe and
  against int4 (whose only candidate is nunchaku) so neither can pass for the
  wrong reason. `GEN_WORKER_NATIVE_KERNELS` is deliberately NOT deleted here —
  it gates an unshipped rollout rather than switching a finished feature, and
  removing it forces an activate-or-delete decision on the native-kernel
  subsystem itself; reported for an owner instead of resolved blind.
