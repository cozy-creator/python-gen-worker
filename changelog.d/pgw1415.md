- **Every v2 checkpoint's tuned defaults reach the entrypoint again.** `HubBindingResolver.resolve`
  parsed and validated the hub's `inference_defaults` row and then built `DeployBinding` WITHOUT
  `model=`, so `decode_model_defaults` saw an unclassified checkpoint on every real deployment,
  warned, and served the model type's platform fallbacks. On FLUX.2 Klein Turbo that is **28 steps
  with CFG on for a 4-step guidance-free checkpoint** — a different image at ~7x the cost — and the
  same silence covered `sdxl`'s `step_distilled`, `sd15`'s step recipe and `wan-2.2`'s per-repo
  knobs. The row now travels resolver → binding → `ctx.defaults()`, measured on the real chain:
  `flux2-klein` serves steps 4 / cfg False where it served 28 / True.

- **The cause was a WIRE COLLISION, not a missing argument, and it is the part worth remembering.**
  tensorhub's th#2140 landed `ModelBinding.model = 9`; this repo's vendored copy still called tag 9
  `manifest_digest` (th#1941). Both are strings, so nothing failed to parse — the hub stamped a
  model NAME into the slot this worker reads as a fetch POINTER. th#1941 claimed 9 here while
  tensorhub still had it free, and the two protos then meant different things by one tag for a week
  with no gate catching it: `proto-drift-check.sh` layer 1 only proves each copy matches its OWN
  recorded digest, and the two copies are *deliberately* divergent, so the divergence that mattered
  looked exactly like the divergence that was fine. **`manifest_digest` moves 9 → 10** — the tie
  breaks toward the field with a live SENDER, and tensorhub stamps `model` on every dispatch while
  nothing has ever sent `manifest_digest` (th#1941's hub leg still owes it, now at 10).
  `LoraOverlay.model = 4` is vendored in the same pass so the adapter half of the pair is not the
  next repeat.

- **A row without its name is now a typed refusal, not a quiet downgrade.** The hub's `model` column
  is `NOT NULL` beside the defaults JSONB (th#2140 migration 0104), so defaults arriving with no
  classification is a pair that broke in transit — precisely this defect's signature — and the
  resolver refuses naming it. The genuinely unclassified checkpoint (no name, no row) keeps
  pgw#1377's warn-and-serve arm untouched: that arm was always correct, and the decode matrix is
  not re-litigated here.
