- **pgw#566: every kohya SDXL adapter works on the branch-capable lanes again.** Two causes, both closed. (1) `normalize_adapter_state_dict` passed `unet_config` only to converters with a NAMED `unet_config` parameter — and diffusers' real `StableDiffusionXLPipeline.lora_state_dict` takes `**kwargs`, so on the one class that needs it the SGM block remap silently never ran. The converter renamed kohya's block indices without remapping them (`unet.down_blocks.4.1…`; SDXL has down_blocks 0-2) and `map_adapter` then failed loud with 2166 unresolved keys, killing the request typed on w8a8/compiled lanes since 0.33.0 — i.e. most of civitai's SDXL catalog. (2) The only guard against a bad conversion was gw#627's `.processor.` NAME test, which caught the family it was written from and nothing else; half-converted SGM indices contain no `.processor.` and sailed through. The normalized dict is now PROVEN to resolve — if it leaves strictly more denoiser keys unresolved against this model than the raw keys do, the raw keys are kept and `map_adapter`'s own kohya/SGM grammar maps them (722/722 modules on the live repro). The check asks `map_adapter`'s own oracle (`_group_keys` over `branch_modules`), so guard and mapper cannot drift, and an unanswerable probe never decides.
