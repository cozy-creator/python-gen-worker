- **pgw#1599: `lanes=` is REQUIRED on every `Model` subclass, its value is a demand FORMULA, and five vocabularies are deleted.** Paul's ruling pair (2026-08-20): a lane answers checkpoint compatibility and lane selection, not merely compilation, so there is nothing an implicit, borrowed or derived lane could stand in for — and *"there is no 'eager only' … simply do not include any `ctx.compile()` invocations"*. The header is now `lanes={contract: lane(request=const(GiB(1.2)) + per_mp_batch(MiB(220)), resident=("vae",))}`, with the demand term algebra in `gen_worker.demand` (lock-time evaluable, serialized into the release document so tensorhub can price a pod without running Python; pgw#1600 fills in evaluation behind the same surface). Two optional class kwargs join it: `structural={axis: Structural(field=, classes=, measured=)}` makes a program fork enumerable — the derive traces ONE representative per variant class, so sdxl's scheduler timestep-dtype pair costs 2 traces and covers 8/8 schedulers where 5 of 8 previously fell to loud eager — and `shapes={"aspect": STATIC|DYNAMIC}` moves pgw#1548's per-model choice onto the model that measured it. `batch` is not declarable: CFG is a permanently static fork. **Deleted, hardcut:** the machine-floor strings (`"vram7g"`) — `min_sm` survives DERIVED from the contract dtype, now per-lane on `DeclaredLane`; `ModelType.canonical_contract` and all 14 assignments; `eager_only=`; `lanes=()` and the whole `DerivedLane` machinery; derive's global `DYNAMIC_AXES` flag and `--dynamic-axes` on `lock`/`release derive`. Each refuses by name at class-definition time, pointing at what replaced it. The pgw-side `lora_bucket` vocabulary — a dead axis nothing ever set non-zero — is swept with them. New consumer surface: `model_declared_lanes(cls)` answers `(contract, handle, dtype, derived min_sm, demand formula, residency)` computed at class definition, so nothing downstream re-parses a stamp or re-derives a floor.
- **pgw#1599 (admission half): the lane VRAM floor pgw#1590 built its charge cap on is deleted with every other floor string, and the over-charge stands — deliberately, with the three rejected replacements measured and recorded.** pgw#1590 fixed a real refusal (minimax-h3's DiT lane needing 180 GB on an 84 GB H100 that had served it) by capping `admission_charge` with the endpoint's hand-written `vram78g`. Three replacements were built and measured before the cap was dropped rather than re-plumbed, and **each can UNDER-count, which is the direction that OOMs a rented card instead of refusing**: summing the tensors a lane's CONTRACT claims (a contract is a matching-set template, not an inventory — h3's declares 10 patterns); charging only the FILES a contract claims a tensor in (coverage is not consistent across the fleet — `sdxl.diffusers-bf16` covers unet + vae + text encoders, `sd15.diffusers-bf16` covers the UNET ONLY, so narrowing sd15 would drop components it holds resident); and charging at the contract's dtype (h3's bf16 contract honestly says ~133 GB, and the gap to the ~66.5 GB it holds is a RUNTIME `quantize_()` inside `setup()` that no manifest, header or contract can see). **That last one is the finding, and it is not an admission defect:** h3's load-time quantization is the undeclared numerics change pgw#1605 exclusion 1 bans, and pgw#1590's hand-written 78 was load-bearing precisely because it encoded the violation's consequence. The close is h3 serving a real `minimax.h3-dit-fp8-rowwise@1` lane (it exists, `float8_e4m3fn`), which needs tensorfs#128's converted artifact and pgw#1606's loader — not a cleverer sizer. `admission_charge` is now a single-producer function of the sizer's two numbers with no cap and no floor, its confession says UPPER BOUND and names what actually fixes it, and `tests/test_admission_lane_declaration_pgw1590.py` asserts the h3 refusal byte-for-byte so the day it stops being true a test says so instead of a pod. The regression is LATENT: endpoints pin gen-worker from PyPI and this code reaches h3 only at a version cut it adopts.
- **pgw#1599 (placement half): the degraded-placement warning is NARROWED, not deleted, and a test proves it can still go red.** `warn_if_degraded` had two arms — an unmet `min_sm` and an unmet VRAM floor. The VRAM arm's only input was the floor string, so it is inert until pgw#1600 computes `weights + demand(envelope)` and gives it a better one. The `min_sm` arm is untouched and still derived from the lane contract's own dtype: a real bf16 lane on a machine with no CUDA device still warns loudly and still serves (degrade, never refuse). Stated this way because "the warning did not fire" is only honest evidence when something else proves it CAN — so the assertion that a float32 stand-in lane reports NOTHING sits beside a test that a real lane on a CPU-only host reports a `min_sm` shortfall. The publish block loses `min_vram_gb` with it: `functions[].resources.requires` now carries only terms DERIVED from the contract, with nothing in it typed by an author.
