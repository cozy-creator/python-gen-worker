- **The adopt-only serve role: a pod that cannot compile, and whose every miss is an
  answer.** `executor.py` was both hosts in one class — it served tenants and imported
  `mint_supervisor` at module scope — so "this pod cannot compile" was a claim about
  intent with nothing enforcing it. DESIGN-RULINGS §4.28/§4.29/§4.30 leave exactly two
  kinds of serving pod, and `gen_worker.serve` now makes the difference a process
  boundary instead of a code path.

  `gen_worker.serve.role` declares the two roles and, in one place, the two module sets
  that define them: `SERVE_ROLE_MODULES` (what the adopt-only path executes) and
  `MINT_MACHINERY` (the nine modules it may not reach). The role is **declared by the
  process entry** — `python -m gen_worker.serve` is the adopt-only worker — and
  deliberately not an env knob: §1.17 keeps a DECISION out of the environment, and
  pgw#1327 already refused a `GEN_WORKER_ADOPT_ONLY` for this exact question.

  Both halves of the guarantee ship, and neither subsumes the other.
  `scripts/lint_serve_role_closure.py` (a `fast gates` step, superseding pgw#1327's
  narrow `lint_serve_keyset_closure.py`) walks the role's transitive static import
  closure — **function-local imports included**, which is how `fleet_cells` reached the
  lane — and reds on any reach into the mint machinery; it reads both lists out of
  `serve/role.py` rather than holding a second copy, because this repo has already
  shipped a fence naming a deleted symbol and stayed green for months (pgw#1176). At run
  time `gen_worker.serve.guard` puts a finder at the front of `sys.meta_path` so importing
  any of those modules raises `MintMachineryUnavailable` — which covers what a tree walk
  structurally cannot see: a computed module name, and the tenant's own endpoint code.

  **The fence changed the design while it was being written.** Its first two shapes were
  red, correctly: a `supervision()` that imported its own eager implementation — even
  lazily, even inside the function — put the whole lane back in the role's closure. So
  the dependency inverts. `serve.mint_seam` knows only a Protocol and `NoMint`;
  `gen_worker.mint_adapter` registers §4.28's eager-capable implementation as a side
  effect of being imported, and the process entries are what import it.

- **A miss REFUSES or ROUTES, and the difference is decided once.** An eager-capable pod
  answers every adopt miss the same way — serve eager, mint in the background — so the
  miss never had to be stated precisely. `serve.refusal` states it: a closed `MissKind`,
  a `Disposition` per kind that is **total with no default member**, and the evidence —
  which key, which tcg#37 selection outcome, which candidate classes missed and why.
  `serve.boot_miss` maps every reason in `boot_adopt.REASONS` an adopt-only pod can
  reach, checked total at import; the twenty tracer tokens are deliberately UNMAPPED and
  raise, because pgw#1327 made the key deriver an injected parameter and this role
  injects none, so reaching one means the role's premise is broken. The disposition is
  what the wire carries: `_map_exception` turns ROUTE into `RETRYABLE` (the hub places
  the work elsewhere) and REFUSE into `FATAL` (re-placing it buys a second identical
  failure), and every refusal emits one `adopt_refused` activity event whose `phase` is
  the countable token.

- **tcg#37's `ingress_selection_v1` is adopted: ranking is read from the contract, not
  re-derived here.** `EntryDispatch.select` walked the armed classes with this module's
  own `ingress_report` / `miss_distance` / `MISS_RUNGS`, so a second serve host would
  have had to reverse-engineer the admission rule from Python source. It now goes through
  `torchcg.selection` — all-or-nothing admission, `>1` admitting class as a defect rather
  than a coin flip, the dims-last rung table, and the two normalization domains — and the
  rung table, `AOTI_ALIGNMENT` and the recast domain are read from the contract instead
  of spelled twice. The refusal WORDING stays ours, which is what tcg#37's scope guard
  says it should be.

  The verdict is a VALUE before it is an exception, and that is what lets one walk serve
  both roles: the eager-capable host renders it as `IngressContractError` and falls back,
  while `StoreArmedGraph` — pgw#1329's arm with no `nn.Module` anywhere on the path, and
  therefore no eager tier to fall back into — raises the typed refusal carrying the
  ranking. `selection.py` and `ingress_selection_v1.json` are vendored additively at
  tcg#37's merge; the rest of the snapshot stays where it is, because upstream's tip also
  renames the compiled-graph ref prefix and would orphan every artifact this fleet has
  stored. The split is declared in `_vendor/VENDORED.toml` and digest-fenced like any
  other vendored file.

- **Found while rebasing, and worth its own note: registration by process entry was an
  ordering hazard.** The first shape of the seam registered §4.28's implementation from
  the three process entries (`entrypoint`, `cli`, `local_serve`). Every test that drives
  a background mint then depended on one of those having been imported into the same
  pytest worker by some unrelated file — so `test_executor_adopt` passed under one file
  ordering and failed under another with the mint silently never completing. Registration
  now happens in the two modules that CALL the seam, which is where the dependency
  actually is, and a subprocess test proves it in a process that imports exactly one of
  them and nothing else. The seam also refuses loudly rather than answering `NoMint` when
  nothing registered in the eager-capable role: quietly answering would have turned
  "nobody registered" into "this pod stopped minting", which is the silent capability
  loss that made the hazard invisible in the first place.
