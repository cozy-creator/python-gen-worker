- **pgw#1032 (HARDCUT, paired with tensorhub th#1702): the worker stops
  advertising COMPUTED cell keys as deliverable demand, and the 660-line
  adoption handler nothing has ever dispatched is deleted.** A worker holds two
  key digests of identical `ck<n>-<56 hex>` shape and disjoint spaces: the
  COMPUTED key (`cell_key.compute`, hard-coded `kind="inductor"`) and the
  STAMPED key (`aot_mint.cell_identity`, `kind=aot_serve.ARTIFACT_KIND` —
  `"aot-inductor"`). `kind` is inside the canonical axis set the digest covers,
  so the two can never be equal. **Since pgw#1010 the AOT export is the only
  mint any pod runs** — JIT intake compiles in this process and names no
  artifact at all — so nothing has produced an `inductor`-kind artifact on any
  pod since, and every hub mechanism keyed on exact equality with a computed key
  (store-lookup delivery, HelloAck snapshot attach, the `ADOPT_COMPILE_CACHE`
  hot push, the `cell_demand` ledger) was structurally unable to fire. The
  worker was feeding all of them.
  - **The producer is gone.** `_CompileTargetRecord` loses `requested_cell_key`
    and `requested_cell_axes`; `_refresh_compile_target` no longer computes a
    key; `compile_targets()` stops filling those two `pb.CompileTarget` fields;
    `Executor.cell_lookups()` is DELETED with its `lifecycle` and
    `procsplit.merge` wiring — it advertised up to five SPECULATIVE per-lane
    computed keys per declared spec into the same dead space. **The proto fields
    are untouched**: their retirement belongs to the th#1457/pgw#891
    `ExecutionSpec`/`RunJob` cut (`proto/` is a vendored byte-identical copy
    gated by `proto/PROTO_DIGEST` in both repos, so a one-sided edit fails CI by
    design). A target now states only the identity it IS serving.
  - **`ADOPT_COMPILE_CACHE` is deleted end to end**: `Executor.handle_model_op`,
    `_handle_compile_cache_adoption`, `_adopt_compile_cache`, `_adoption_event`,
    `_adoption_intent`, the single-flight adoption lock, and
    `Lifecycle._adopt_compile_cache_then_delta`. A `model_op` on the wire is now
    logged and ignored rather than refused, so a hub that has not yet deployed
    th#1702 cannot lose its stream over it. `compile_cache.arm_staged_artifact`
    — the STRICT arm entry point that existed only for hot adoption — goes with
    it; `stage_artifact` stays (`seed_artifact` and `enable` are live callers).
  - **Gone with the operation, because each only ever described one:** the
    per-target `failed_compile_identities` quarantine (the process-wide
    `record_cell_quarantined`/`cell_quarantined_in_process` pair is the half
    `fleet_cells` actually reads on the arm path, and is unchanged),
    `active_adoption_operation_id`, and the causal
    `adopt_failed:runtime_guard` ModelEvent. Runtime-guard revocation itself is
    untouched: the target drops its active identity, the record keeps serving at
    explicit eager, the cell is quarantined process-wide, and the dispatch fence
    refuses the pinned run. `compile_cache.build` loses its `requested_cell_key`
    echo — the forge that issued demand-driven mints was deleted in th#1127 and
    no caller has passed it since.
  - **`_warn_cell_key_divergence` dies with the divergence it warned about.**
    pgw#1033 landed the interim (return early on an AOT ref) and named this
    issue as the deleter; the premise — that a self-minted cell's key should
    equal the key this runtime computes — was false for every mint there is, so
    the ERROR fired on every healthy AOT boot.
  - **NOT DONE, and the issue's fourth box is withdrawn: `serving_tier` and
    `serving_mode` must NOT be reconciled onto one authority.** The issue read
    their disagreement on a JIT-intake pod (tier `eager`, mode `jit_cell`) as a
    defect. It is the design, asserted deliberately from the other side by
    `test_guard_miss_pgw680::test_tenant_guard_miss_end_to_end`,
    `test_eager_first_boot_pgw671` (x2) and
    `test_boot_compile_deferral_gw584::test_w8a8_setup_without_cell_degrades_to_explicit_eager`.
    They answer different questions: `serving_mode` is *what code ran this
    request* (an intake arm honestly runs compiled graphs), while
    `serving_tier` is *is this worker serving from a CELL* — and the hub reads
    the tier as ADOPTION EVIDENCE (`WorkerServingCompiledTier` ->
    `WorkerAdoptedDeliveredCell`, th#1216 capacity economics), so an intake pod
    reporting `compiled` would testify that the store-to-worker cell exchange
    worked on a pod that adopted nothing. `serving_tiers()` is unchanged; its
    docstring now states the boundary so the next reader does not re-merge
    them, and the new test file pins it.
  - **Not touched, deliberately:** discovery/fetch-and-filter (`aot_cells`,
    `fleet_cells`' arm path, `local_cells`) and `cell_key.compute` itself, which
    keeps live callers in all three — the COMPUTED key is still the correct ARM
    identity, it is just no longer advertised as demand. `_fetch_compile_snapshot` stays for pgw#904's `Arm.artifact` lane
    — though note it is now DARK, because th#1702 deletes the hub's snapshot
    attach as well, so nothing fills the map it reads. **Nothing is pushed to
    a pod any more**: a cell is ACQUIRED by `aot_cells` fetch-and-filter at arm
    time, and the comments in this cut say so rather than naming a delivery
    path that no longer exists.
  - **Tests:** the hot-adoption suite in `test_executor_adopt.py` (the `_adopt`
    harness, the success/classified-failure sections, target-replaced, republish

  - **One fixture gap found and NOT fixed here** (no behaviour depends on it, so
