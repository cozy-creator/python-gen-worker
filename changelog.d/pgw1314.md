- **pgw#1314 (COMPATIBILITY program, 2 of 9): `cuda_version` reaches the hub
  from a LIVE worker.** `WorkerResources` grows field 14, populated from
  `HostFacts.cuda_version` through the single
  `procsplit.parent.ParentControl._parent_resources` path — no second builder
  (pgw#898). The fact was already measured and was LOCAL ONLY: its one carrier
  to the hub was `HardwareUnsuitable.torch_cuda_version`, so the hub could
  learn a worker's CUDA version from exactly one kind of worker — one that had
  already died. `min_cuda` is a requirement term (pgw#1313), and a term whose
  fact never arrives from a healthy worker is a requirement that silently does
  not hold.

  ABSENT stays distinguishable from measured: an unreadable CUDA runtime
  leaves the field off the wire rather than shipping `""` as an answer, and
  `parent.py`'s existing rule is unweakened — an unmeasured HOST still ships a
  Hello with NO `resources` at all, loudly, never a partially-filled struct.

  `vram_free_bytes` stays LOCAL, deliberately: free VRAM is a MOMENT, not a
  machine fact. It drives the rung walk and must never become an admission
  input.

  The spelling trap is settled rather than deferred: the SM axis is BARE
  (`"90"`) on both sides of the wire and in `min_sm`, which is what
  `HostFacts.gpu_sm`, `WorkerResources.gpu_sm` and
  `contractspec.DecodeEntry.MinSM` already say. Anything dotted is a
  normalization at its own boundary. The proto digest moves with the contract;
  tensorhub's canonical copy is th#2072's paired change.
