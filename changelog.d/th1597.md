- **th#1597 (BREAKING, wire protocol): the worker↔hub contract is
  `cozy.scheduler.v1`, and the major now lives in the service path.** Per
  DESIGN-RULINGS §1.27(b) the wire-protocol MAJOR is the proto package, so it is
  in the gRPC method path — this client dials
  `/cozy.scheduler.v1.WorkerScheduler/Connect`, not the unversioned
  `/cozy.scheduler.WorkerScheduler/Connect`. Routing selects the contract before
  a byte of the message body is interpreted, so an unsupported major is refused
  by gRPC itself rather than by a check somebody has to remember to write.
  §1.27(g) sets the first package at `v1`: `PROTOCOL_VERSION_CURRENT` is **1**,
  not 5. Versions 1-4 never existed as packages, so nothing is being renumbered
  past a real history — 5 was a label with none behind it, and nothing
  pre-launch may assert one it does not have.

  **This is a hard cut with no dual-dial window.** A worker built from this
  release cannot talk to a hub older than tensorhub's matching cut, and a worker
  from ≤0.92.x cannot talk to a hub at v1. Hub and fleet move together.

  §1.27(f): `reserved` is scoped to one major and is not inherited across one,
  so v1 numbers densely from 1 in every message and enum and carries no reserved
  slot at all. Reclaimed: `HostCanary.h2d_gbps`, `ResolvedCompute.gpu_count` /
  `vram_gb`, `ModelOpKind`'s three retired kinds, `BootPhase.graph_class`, the
  dead `HelloAck.keep`, and `StateDelta`'s never-reserved 10/11 hole. Every
  producer in this repo builds these messages by keyword, so the renumbering is
  invisible to worker code.

- **th#1597: `UNIMPLEMENTED` on `Connect` is fatal, and it had to be made so
  before the path could move.** It was previously unhandled — it fell to the
  generic `stream error` branch and reconnected with backoff, forever. Once the
  major is in the path that is precisely the wrong-major signal, so a worker
  pinned to a major its hub does not serve would have looped invisibly. The
  fatal exit is load-bearing HUB-side, not tidiness here: the worker dying
  pre-Hello is what leaves `everConnected` false, which is how tensorhub's
  th#874 death taxonomy marks the release `boot_crashing` and fails its queued
  requests. Retrying would have produced no durable mark and no operator signal
  — strictly worse than dying. Covered by a real gRPC server registered under
  the pre-v1 service name (`tests/test_wire_major_th1597.py`), which is the
  production shape of "new worker, hub not yet cut over"; the assertion is on
  the typed reason, not merely on the exit code.
