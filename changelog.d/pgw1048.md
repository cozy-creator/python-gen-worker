- **pgw#1048: a component the composition names and the dispatch does not
  supply is a TYPED refusal, not a retry-loop on a nameless `OSError`.**
  pgw#1047 measured the shape on a paid L40S: the hub's seed path dropped the
  sdxl deploy's `vae` component override (th#1715) while th#1711 had already
  narrowed the outbound snapshot to exclude `vae/`, so the pod loaded a
  composition with nothing substituted and diffusers raised `OSError: Error no
  file named config.json found in directory <snapshot root>` — naming neither
  the component nor the cause — which the rotation preloader then retried on
  every desired-set generation for nine minutes, until the hub reaped the pod.
  The root cause was hub-side and is fixed; this is the worker's half.
  `load_from_pretrained` now pre-validates the composition on the non-modular
  lane (`assert_composition_satisfiable`): every component `model_index.json`
  names must arrive either from its own dir in the local tree or through the
  pgw#617 `components=` injection, and one that does neither raises
  `ComponentSubstitutionError` carrying `missing`/`expected`/`injected`/`tree`
  and emitting a typed `component_miss` activity event (`phase=refused`) to the
  hub — the modular lane's `ModularHydrationError`, one lane over. Skipped, as
  compositions that are not the tree's to satisfy: index-less layouts
  (single-file, transformers, root-layout quantized artifacts), the svdq lane,
  gguf snapshots, and — per component — anything the index names that the
  pipeline class's own signature does not, which is diffusers' own
  `_get_signature_keys` rule, so the guard can never refuse a load
  `from_pretrained` would have completed. The rotation preloader classifies the refusal terminal for
  the *dispatched identity* — the desired-instance bytes, not a timer and not an
  attempt count — so a hub that repairs the binding self-heals on merit while a
  re-sent identical instance is never re-attempted; ordinary stage failures keep
  the pgw#760 retry-on-next-desired-set shape.
