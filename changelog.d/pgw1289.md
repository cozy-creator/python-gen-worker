- **A mostly-resident snapshot stops reporting zero progress while it re-hashes tens of GB.**
  `_ensure_objects` filters residency BEFORE calling `download()` and emitted `progress(done, total)`
  exactly once, after the whole filter loop. Every check is a full sha256 re-hash, so the
  hub-visible counter sat pinned at zero for the entire scan and `download()` — where pgw#1287's
  tensorfs-side fix lives — was never reached. The hub's transfer freshness window is six minutes
  and two zero-progress pods arm a release-scoped fault brake, so a pod that had already done all
  the work condemned itself, and worse on every retry because the loop re-verifies everything.
  `progress` now fires before the loop (the total is known up front) and after every grant.
- **The scan no longer holds the event loop.** It ran on the caller's loop thread: 1008 MiB resident
  blocked the loop for 1017 ms continuously, so the heartbeat coroutine and every queued DOWNLOADING
  event were stranded — an emission that could not leave the process. Each check now runs under
  `asyncio.to_thread`, one grant at a time; no parallelism added and no `contains` semantics changed.
  Same probe after: max loop gap 1017 ms → 37 ms.
