- **pgw#1232 (DESIGN-RULINGS §1.38b): the compiled-graph artifact format starts at v1, and its
  axis name is qualified.** `aot_serve.ARTIFACT_FORMAT = 3` becomes
  `COMPILED_GRAPH_FORMAT = 1`, and the metadata key and arm axis it is stamped/compared under
  rename from the generic `format` to **`compiled_graph_format`** (both read from one symbol,
  `COMPILED_GRAPH_FORMAT_KEY`, so the stamp and the comparison cannot drift into two spellings).
  Paul: *"we are pre-launch, so we should be on v1 for everything, including our compiled-graph
  format."* The version records the first contract we ship, not the count of abandoned internal
  prototypes. **Hard cut:** no 3→1 mapping, no accepted set — an artifact of a retired format is
  refused by name, which is what makes a v1 reader unable to consume one. The ruling names the
  generic `format` as what let pgw#1230 compare the AOT package schema against an unrelated
  torch-inductor semantic-cache epoch, costing a fully compiled 4-class mint. Verified free before
  shipping: `cell_store` 0 rows, zero `cg-key-v1` objects anywhere durable, and no hub code reads
  or compares the axis.
- **pgw#1232: the two 64-bit chokepoints under the `graph` key axis are derived and documented
  rather than inherited.** `graph_hash._DIGEST_HEX` and `aot_serve.class_hash`'s own truncation are
  both 16 hex, and the axis has the MINIMUM of the two — so widening either alone re-keys the whole
  corpus and buys nothing. Kept at 64 bits with the birthday bound written at both sites
  (P ≈ N²/2⁶⁵: ~3e-12 at 10⁴ graph classes, ~3e-8 at 10⁶), and with the both-or-neither rule stated
  where a future widener will read it.
