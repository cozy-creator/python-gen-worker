- Compile-span attribution is `torch_compiled_graphs.spans`, and `gen_worker/aot_compile_spans.py`
  is deleted. It was a duplicate implementation, not a similar one: every module constant —
  `SPANS_V`, `PARTITIONS`, `PARTITION_KEYS`, `RESIDUALS`, `SUBSPANS`, `OVERLAY_KEYS` and even
  `__all__` — compared byte-equal against TCG 0.4.0, and `SpanLedger` matched down to
  `start_epoch`, the wall-clock twin the parent/child spans are closed on. So this deletes 299
  lines and changes no measurement. The seven test files that exercised the partition now import
  it from TCG and keep every assertion: pgw asserting the partition it writes into is a
  cross-package contract fence, which is worth more than the duplicate it replaces.

  Two things the compiler found that a plan would not have. `warm_spans.py` does **not** die with
  it — the JIT ledger has its own key set on purpose, and `activity.py` still consumes it; it
  migrates. And `aot_compile_pool._CONTRACT_MODULES` drops to the two LOCAL modules, because the
  span partition now ships in a pinned wheel: `CODE_DIGEST` guards against a stray second
  `gen_worker` on the path (pgw#840), not a stray TCG, and the report already carries `spans_v`
  for the partition's own shape. `CODE_DIGEST`'s value changes as a result, which invalidates
  `aot_resume`'s local memo — a cache miss, pre-launch, and that module is already condemned.
  It is not a `cg-key-v1` axis: the key is exactly `graph` x `sm` x `toolchain`, and no published
  compiled-graph key moves.

  First slice of pgw#1270, the compiled-graph half of pgw#1232. It does not rebase or replay
  PR #807 — that branch is welded to a Tensorhub wire lockstep, a twice-NO-SHIP store sidecar and
  corpus packaging master has since landed itself, so each slice is regenerated from master with
  #807 read only as a reference.

  Compile and measurement children now open TCG through one worker engine factory. Measurement
  compiles into a temporary HashRepo CAS that disappears with the report, while a real mint keeps
  the canonical worker CAS. The recipe process releases its now-dead resident pipeline before the
  K compile children start, and the former kernel-lane A/B probe is removed because its result
  never reached either the compile child or TCG's closed artifact metadata.

  The worker tests now stop at the public TCG boundaries they actually consume. They retain the
  declaration, adapter fan-out, literal, input-guard, compile-pool durability, resident release,
  latent-basis refusal, measure-only cleanup and span-partition red proofs, while deleting suites
  whose only subjects were the five removed worker implementations.

- **The boot-memo honesty gate survives the cut, in TCG's shape.** `mint_supervisor.rule_on_boot_memo`
  (pgw#1271) calls `boot_key.assert_memo_honest` at the seal/publish seam. The memo now stores TCG
  class hashes rather than worker keying blocks, so the check compares hashes directly — and since
  `graph_witness` is one of the facts TCG folds into `class_hash`, a stale witness can no longer
  survive a matching hash. `aot_serve.stamp_entry` is gone with the worker's own stamping code.

- **`aot_serve.runtime_key` is deleted, not delegated.** pgw#1271 made it a projection of
  `compile_cache.runtime_key` because it had been a second, silently-failing torch probe. The cut
  removes its last caller, so the duplicate implementation goes entirely: one runtime probe because
  there is one function.

- **No fleet-declared config name is retired here.** `aot_wrapper_split.py` read
  `GEN_WORKER_AOT_RUN_IMPL_SPLIT_OFF`, so the read site and its `config_reads_allowlist.txt` row die
  with the module — but the NAME stays accepted by `config.loader._OWNED_NON_SETTINGS`, along with
  `GEN_WORKER_AOT_HOST_COMPILE_JOBS` and the two `GEN_WORKER_MINT_RESUME_*` names. The last measured
  census (2026-08-03) found five SDXL releases declaring the split switch and one live endpoint
  entry, and nobody has re-queried the standing hub since. Dropping a name a deployed pod declares
  fails its config load; the envs are inert either way. Retire them on a fresh count of zero.

- **Six suite rows the cut broke, and one it did not fix.** Four were fixture drift against
  TCG's closed types (an empty `CallIngress.parameters` TCG now refuses; a lost trailing comma
  that made `EntryDispatch.runners` a flat pair; a `monkeypatch` at `aot_mint.export_declaration`
  after it moved to `api.export_contract`; the dynamo CONTROL arm carrying a `cg-key-v1`-shaped
  ref, which makes `is_aot_ref` claim the exported lane and scores the arm on the wrong failure
  detector). Two lost their subject and are retargeted at the surviving one: the pgw#1098
  two-reader asymmetry (there is one bounded envelope reader now) and th#1423's
  credential-at-use-time (`Executor._cell_publisher`, the one publisher construction site left).

  The sixth was NOT fixture drift, and is fixed at the source. `_tcg_runtime`
  read `runtime.get("sm") or "cpu"`. TCG's target vocabulary really is `cpu` or a
  concrete `sm_NN`, and `cpu` is keyed honestly as `cpu-<isa>` — so NAMING it is
  legitimate. CHOOSING it is not, and that `or` chose. TCG keys at COMPILE time
  where the worker used to key at packaging (`cell_key.from_axes` refuses a
  missing `sm` outright), so the identity decision landed on a line that silently
  took the CPU lane: a cardless mint child compiled, keyed and reported MINTED,
  and the artifact it published was TRUE and unadoptable — no GPU pod computes a
  `cpu-avx512` key, so the mint was burnt and the family would re-mint on every
  boot, forever, with nothing anywhere saying why. pgw#985's "a deterministic
  refusal buys no second pod" was gone.

  `compile_cache.compile_target_block()` is the one home for the decision,
  shaped like `arming_block`: side-effect free, it only NAMES, and it reports
  through the three-valued `hostfacts.cuda_state` so "no card" and "card would
  not answer" stay different pod verdicts. `mint_child.mint` refuses on it
  (`PreflightRefused` -> `EXIT_REFUSED`, `retryable=False`) as its LAST
  preflight — after the wiring, traceability and handler-proof refusals, which
  are more specific statements than "this box has no card", and still before
  every export, compile child and published byte. `_tcg_runtime` keeps naming
  `CPU_COMPILE_TARGET` explicitly, because the measurement CLI and the CPU-lane
  compile tests are legitimate CPU compiles; what it no longer does is decide.
  Red-verified: a mutant that neuters the block lets a target be built with no
  `sm` at all.
