- **pgw#1079 (ie#638): the mint stages EVERY resident pipeline slot out of VRAM,
  not just its own.** pgw#1053 shipped the release — a serving process's eager
  pipeline moved to host RAM for the life of a mint, gated on the typed goal set
  so it fires only where no serve goal is held — and it released
  `MintTask.pipe`, one pipeline object. z-image's endpoint is ONE class with TWO
  `ZImagePipeline` slots, so the sibling slot rode the whole export resident:
  42.53 GiB of a 79.25 GiB card, a 46.42 GiB ceiling for the export child, and
  7.38 MiB free when `torch.export` asked for 76 MiB (ie#638, measured twice in
  one pod, deterministic, with the pgw#992 census already clamped to K=1).
  `mint_budget.co_residency` prices that ceiling as `free - activation`, so a
  resident byte in the parent is a byte the child cannot have, one for one.
  `MintTask` now carries `pipes` — every slot the record holds — and
  `park_residents` stages all of them, deduplicated by identity so two slots
  sharing a component neither move it twice nor double-count it. The condition
  is unchanged and remains the goal set, never an env switch: a serving pod
  keeps eager resident and hot, and its mint may simply not fit, which is the
  existing, safe outcome. Restore runs before ADOPT and PARITY, so the eager
  comparison oracle is back before anything compares against it.
- **The ie#638 arithmetic is now typed, on BOTH legs.** Every mint attempt emits
  one `residents`-phase event carrying what was released, what the parent still
  holds, the card's free bytes and the export child's ceiling — and, when
  nothing was released, WHICH reason (a serve goal held, or nothing resident).
  A mint that dies of device memory no longer requires reconstructing those
  three numbers from an allocator message.
- **Two new gauntlet members, both proving on a 1.1 MB model what a rented A100
  could not afford to ask.** `micro-residency` / `micro-residency-serve` hold two
  resident slots with 3 GiB of ballast and differ only in POSTURE: the mint-goal
  leg releases, exports, restores and passes parity; the serve-goal leg keeps the
  tenant resident and the mint declines on `insufficient_vram`. `micro-pad32`
  carries ie#637's surviving watch item — a dynamic dim whose extent is
  `32*FloorDiv(L+31,32)` over a token count that is itself a product of two
  declared symbols — and serves three L values whose pads are 0, 16 and 28 from
  ONE collapsed artifact.
