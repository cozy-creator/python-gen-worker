### The worker cuts to tensor-layout contract v2 — a lane is a (topology, quant) pair, and the sm floor falls out of the rule (pgw#1621)

Vendors tensorfs `afdf321` (tensorfs#151) and completes step 3 of the v2 hardcut
(tensorfs#151 → th#2250 → **pgw#1621** → th#2251). A v2 LAYOUT is
`quant(topology)`: a TOPOLOGY (a finite `{key → logical shape}` map, dtype-free,
extracted mechanically from a reference checkpoint's headers) composed with a
QUANT RULE whose convention facts — nibble order, swizzle, scale rank and span —
ARE its identity. Thirteen documents replace thirty.

**The declaration surface is re-keyed and nothing else about it moves.**

```python
lanes={("sdxl.diffusers@1", "plain.bf16@1"): lane(
    request=const(GiB(1.2)) + per_mp_batch(MiB(220)),
    resident=("vae",),
)}
```

Per-lane `request=` formulas, the residency override, the fork axes and every
refusal are se#816's and are untouched. The old spellings (`sdxl.diffusers-bf16@1`)
survive as DISPLAY names on the catalog record — never parsed, never a gate. The
wire rendering is th#1809's `"<topology>+<quant>"`, shared with the hub's
`tensorfs.LayoutID.String` and with the derived-artifact CAS address, so a
spelling drift there is a fork rather than a cosmetic bug.

**Deleted, in the same change:** `KNOWN_CONTRACTS` and its six handle constants;
the five DECODE DIMENSIONS (`elements`/`scales`/`key_topologies`/`file_layouts`/
`bakes`) with `DecodeDimensions` and `implements_contract`; `DTYPE_MIN_SM`,
`FLOOR_LOSING_SPELLINGS` and `capability_floor_for_dtype`; the vendored v1
corpus with `contract.py` and `contracts.py`; `TensorLayoutContract`,
`MissingContract` and the fifteen `_library` constants; `LaneContract` and
`DTYPELESS_UPSTREAM_LANES`.

Most of those are deleted by making their failure **inexpressible** rather than by
relaxing a check:

* the decode axes were convention facts, and a v2 rule carries its conventions as
  identity — so a decoder names the rule and the axes come with it;
* `capability_floor_for_rule` reads `capability_floor_sm` off the ratified rule
  document, so the `q4_k` and `float4_e2m1fn_x2` spelling traps have no dtype
  string left to mis-spell, and an unknown handle REFUSES where the old table
  answered a silent, permissive `0` (its two zeros — "measured: no floor" and
  "never heard of it" — were the same return value);
* a v2 rule cannot lack a dtype, so the dtype-less lane, its declaration-time
  refusal, its waiver set and the self-deleting-waiver test that guarded it are
  all gone together.

**Two live defects fell out of the re-key.**

* **The lane BODY was keyed on the dtype SPELLING, and two rules share one.**
  `cozy.fp8-storage@1` and `cozy.fp8-rowwise@1` both declare `float8_e4m3fn` and
  execute in different lanes: rowwise stores an F32 `[out]` `weight_scale` and
  feeds the w8a8 GEMM; storage is SCALE-FREE and its own conventions say
  `"consumption": "diffusers layerwise cast to bf16"` — fp8 bytes resident, **bf16
  compute**. The table answered `fp8-w8a8-dynamic` for both, which would hand a
  scale-free tree to a GEMM multiplying by scales that do not exist and floor the
  lane at sm89 for arithmetic it never performs. `_RULE_BODY` is keyed on the rule
  handle, one row per ratified rule, with a gate that fails when a ninth is
  ratified. `unknown_dtype` → `unknown_quant_rule`.
* **The handle grammar refused a hyphenated PRODUCER segment.** `^[a-z0-9]+\.` is
  correct for every v1 QUANT handle — hyphens only ever fell in the FORMAT segment
  — and wrong for half the v2 TOPOLOGY corpus, so `flux2-klein.diffusers@1`,
  `hidream-o1.diffusers@1`, `minimax-h3.diffusers@1`, `z-image.diffusers@1`,
  `ltx2-upsampler.diffusers@1`, `sdxl-inpainting.diffusers@1` and
  `qwen3-6-35b-a3b.transformers@1` all refused as "not a handle". **Five migrated
  endpoints could not have declared a lane at all**, and every test in this repo was
  green. Now transcribed from tensorfs' own `isTFM1ContractName`; a leading hyphen
  still refuses.

  It was caught by running the real `_parse_lanes` over real endpoint `main.py`
  files, and that check is now a test (`test_fleet_lane_rekey_pgw1621.py`) rather
  than a thing that happened once.

**The decode-set wire emits both names, and a SILENCE is why.** `rules` is the v2
name; `contracts` is what tensorhub's `manifestDecodeSetBlock` reads today.
Emitting only `rules` would not have refused — the hub's `DecodeSet` pointer is
nil-able and absence is legal — so the lock would have read exactly like a
pre-census image, the cross-check would be skipped and the key-topology rows would
arrive empty. Both keys carry the same rows and an assertion refuses a tree where
the two renders disagree; `key_topologies` is `[]`, which is the hub's own
UNDECLARED rung and now the only honest value.

**Juggle enforces, it never re-decides.** `admission_refusal` gains an
`ExpectedHeader` arm that diffs a checkpoint's headers against the Go-computed
`quant(topology)` — `LayoutTensor.accepts` for the reference-tolerant keys,
`optional` honoured — and takes the admission verdict as an INPUT. `verdict=None`
REFUSES: the permissive direction is the one that fails silently. `quant(topology)`
is evaluated by the Go engine and by nothing else, deliberately (v1 shipped three
copies of one matching rule and they were free to disagree about an admit), so the
expected header is either binding-carried or a committed `compute_layout` fixture.

**Known gaps, recorded rather than papered over:** five endpoints (flux1,
stable-audio, trellis2, qwen-image, internvl-u) have no ratified topology yet and
are named in `CORPUS_GAP` with a test that deletes each entry's right to exist the
day its pair lands; `read_manifest`'s dtype list has no fp8/fp4 entry, so the v2
byte gate cannot yet run on the lanes v2 exists for; and the binding-carried
verdict has no wire — nothing hub-side populates `DeployBinding.lane_verdicts`.
