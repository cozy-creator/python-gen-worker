- **pgw#1010 (HARDCUT): the JIT/dynamo recipe stops producing artifacts. It
  keeps its serving role and loses its cell.** Paul's ratified reuse ruling —
  *reuse = AOT cells only; JIT = intake mode, honest cold boots* — composed with
  two facts already in the tree: `aot_cells._candidates` rejects
  `kind="torch-inductor-cache"` BY NAME, and nothing else has ever adopted one.
  A dynamo cell therefore had **zero possible consumers**, and every one minted
  spent pod time, a publish quota slot and platform storage on an artifact no
  pod could adopt (attempt 23's `ck5-a53e02a7…` among them). A family with no
  export declaration now serves **JIT INTAKE**: `compile_cache.arm_jit_intake`
  arms the declared targets cold-allowed and guarded, this pod's own warmup
  compiles them, the pod serves compiled for its own life — and nothing is
  captured, keyed, packed, published or owed. Deleted, not gated: there is no
  flag to re-enable dynamo publishing.
  - Gone with it, because each existed only to build or ship that cell:
    `compile_cache.begin_fleet_mint` (replaced by `arm_jit_intake`, minus the
    capture dir) and `finish_fleet_mint`; `fleet_cells.finalize_self_mint` and
    `republish_after_shape_warm`; the executor's in-process/background mint
    driver, its boot-proof pack + gw#612 publish gate, and the shape-warm
    republisher; `mint_child`'s dynamo branch and `_drain_router`;
    `mint_delegate._emit_jit_compile`/`_emit_warm_ledger`. `hot_swap.enable`
    still routes novel shapes eager-while-compiling — it just has nothing to
    republish.
  - **`GEN_WORKER_MINT_IN_PROCESS` is deleted, with the shape it selected.**
    In-process minting existed only to capture and pack a dynamo cell, so "mint
    in this process" is no longer a state this worker can be in. pgw#995 named
    this env the last deletable behaviour switch and its blocker (ten test sites
    forcing the shape through the executor); the shape's removal discharges that
    debt instead of deferring it again. `delegation_refusal()` now always
    returns "" — the PIPELINE half (`fleet_cells.delegation_refusal`,
    `no_eager_tier`) is the only real refusal left. With the process-global
    inductor cache-dir move gone, so are gw#608's delivered-cell-seeded gate,
    pgw#777's multi-execution-group refusal and the one-capture-per-process
    conflict — `EagerPhase` loses `delivered_cell_seeded`, `capture_conflict`
    and `multi_group_in_process`, and `capture_arm_failed` becomes
    `jit_arm_failed`.
  - **A pending IS a mint obligation, and only AOT opens one.** `PendingSelfMint`
    loses `recipe` and `capture_dir` and is `delegated=True` by construction;
    `adopt_delegated_mint` has one arm (`provision.arm_aot`) instead of two;
    `MintRequest`/`MintReport` lose `recipe`, and `MintRequest.capture` becomes
    `work_root` — the child's real work tree, which an AOT mint actually writes
    into, so the mint-liveness byte signal stops reading 0 for every real mint.
    A same-key re-arm in one process now re-arms the finalized cell through
    `arm_aot` rather than `apply(cache_ready=True)`, which would have armed a
    JIT wrapper while advertising an AOT identity.
  - **A MANDATORY (w8a8/w4a4) lane fails closed when the family declares no
    export** (`mandatory_lane_needs_a_cell`). That lane serves only from a cell —
    the th#910 dispatch fence pins every request to an active compile
    incarnation — so a JIT intake arm there would compile a whole boot's worth of
    graphs for a pod that then refuses every request `required_compile_missing`.
    This restores the pre-self-mint posture and is the one behaviour change to
    ratify: to serve a mandatory lane a family must declare an export, because an
    AOT cell is the only cell there is.
  - **Serving mode stays honest**: an intake-armed pipeline reports
    `serving_mode=jit_cell` with an empty `served_cell_ref` (new
    `compile_cache.is_compile_armed`), and reports `eager` again once its guard
    permanently degrades it (the degrade is recorded on the shared failure
    signal). Classifying by the absent ref would have reported every JIT request
    as eager and deleted the JIT arm of the AOT-vs-JIT latency comparison;
    ignoring the degrade would have reported an eager-serving pod as compiled.
    The pgw#680 guard-miss callbacks now bind for anything ARMED rather than only
    for a target that names a cell — gating them on `active_ref` would have taken
    every guard miss on the platform off the wire — and th#1322's `jit_compile`
    duration is emitted from the boot warm window, outside the proof block that
    an artifact-less arm can never enter.
  - **Obligation settlement, verified hub-side, unchanged and correct.** The hub
    seeds obligations per (release, sku) — never from a worker event — and
    discharge already requires a real `cell_store` row
    (`publishedCellSKUsByRelease`/`publishedCellLanded`, th#1644/th#1645), so a
    mint that publishes nothing cannot discharge one. The typed settlement is
    th#1628's: `mint_recipe`'s decline emits `self_mint_skipped` with
    `no_export_declaration` / `declaration_refused` /
    `declaration_module_mismatch`, all of which are in the hub's
    `DeterministicMintRefusalPhases`, so the obligation goes terminally
    `refused` instead of burning two 45-minute boot windows. The decline's text
    now says what the pod does instead ("serves JIT INTAKE … MINTS NOTHING").
    What this cut REMOVES hub-side is a false positive: discharge is kind-blind
    (`cell_store` has no `kind` column), so a published dynamo cell used to
    settle an obligation that wanted an AOT one.
