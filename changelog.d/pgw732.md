- **pgw#732: `Resources` gets a disk axis — `min_disk_gb`.** th#1233 already sizes a conversion pod's container disk from the bytes the job will materialize, so the common case needs no declaration. The residue is jobs whose need is not derivable from the source at all — multi-source marries, large intermediate scratch, and the live example, `mirror_svdq`, which fetches a 13.08 GB nunchaku checkpoint straight from HuggingFace, bytes no catalog read will ever see. The hub half was already wired and waiting (`mergeRequestDiskIntoSupply` honours a per-function `min_disk_gb` as an additional floor, exactly like `min_vram_gb`); nothing emitted it because the SDK had no such field. Named for what it is: a floor the hub may exceed, never a cap, so `min_` rather than a `_hint` suffix. Validated positive at declaration, projected under the hub's own key with no remap, and — unlike `vram_gb_hint` and `compute_capability` — it does NOT imply `gpu=True`, because the case that needed it first is a CPU-only conversion.
