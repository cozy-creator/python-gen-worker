- **pgw#1173: the weight-free premise is FENCED on the boot-trace path, and the fleet evidence that opened the issue is retracted as already-fixed.** The filing read four `boot_adopt child_error` rows — qwen-image 14/14 classes, flux2-klein-9b 9/9, an A100 80 GB, `CUDA OOM left the pipeline mixed-device and CPU rollback failed`, allocator dump listing `transformer…weight` on `cuda:0` — as a live premise breach on a path whose measured high-water is 9.8 MiB. **All four rows are `gen_worker_version 0.104.0`, 2026-08-11 11:00–11:21Z; pgw#1124 fixed exactly that failure and shipped in 0.106.0, tagged 16:46Z the same day.** No row on 0.106.0 or later has ever carried that message. The `transformer` tensors in the dump were the compile target's FAKE parameters, which `device_mismatches` counted as misplaced (pgw#1124 defect 2) so the CPU rollback could never be satisfied; the OOM itself was the serving placement ladder pushing the slot's REAL non-target components onto the parent's card (defect 1). `StructureNotHonored` was silent because the structure WAS honored — a correct silence, not a guard that could not fire. Every `child_error` since is sdxl on a 15.6 GB card, i.e. pgw#1165.
- **Three residual holes in the same premise WERE open, and are now closed.** They are the reason the fence exists rather than the issue simply being closed: (1) `structure_only_components` is an ANY check, so a family declaring two compile targets passed with one of them stranded on real weights; (2) a `place=False` boot trace puts those real weights on the HOST, where `off_host_tensors` cannot see them — both guards green over a composition holding a checkpoint; (3) `_assert_structure_honored` iterated only what the builder BUILT, and `model_index_components` returns the EMPTY SET for any tree with no readable `model_index.json`, so every target was skipped, the guard looped over an empty dict and passed. (3) is the defect class this redesign is about: a guard that cannot fire for the case it is named for, whose silence is then read as proof.
- **`structure_only.assert_weight_free(pipe, targets)`** is the typed fence — an ALL-of check over the declared targets, device-blind, raising `StructureNotHonored`. Target resolution is delegated to `compile_cache.resolve_targets`, the ONE target authority, because a target is an attribute PATH (`transformer.denoise`, `vae.decode` are both declared on the fleet) and a fence with its own weaker `getattr` resolver would read every dotted target as "not carried" and skip silently. Buffers are deliberately not counted — a structure-only component's buffers stay real by construction and a literal-bearing family ships them inside the cell. `boot_trace_child.run` calls it before the export; `_assert_structure_honored` separately refuses a requested target the builder skipped, typed as the BUILDABLE strand so the mint child's fallback to a real-weight export stays correct and stays recorded while the boot trace, which may not fall back, refuses.
