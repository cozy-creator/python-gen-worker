- **The placement stamp is deleted — the worker no longer tells the hub which
  silicon a flavor may run on.** `checkpoints.metadata["placement"]` used to
  carry an SM allow-list, an SM floor and a required-engine list, and the hub
  admitted or refused a card against them. Paul, 2026-08-16: *"pod-purchase
  behavior is only going to depend upon (GPU, lane) ladders set by the
  endpoint-owner"*. tensorhub's readers went first (th#2055, `65f0882f2`:
  `PlacementFromMetadata`, `Placement`, `defaultPlacement`, `admitted()` and
  `AdmitLiteral`'s sm/engine arms), so `models/ladder.py` loses `Placement`,
  `default_placement` and `placement_to_metadata`, and `convert/publish.py`
  loses `_placement_block` and the `placement_sm_allowed` / `placement_sm_min`
  / `placement_engines` override surface. **`precision_class` survives and is
  the only key still written**: `precision.StoredPrecisionOf` reads it as the
  strongest evidence for a stored class where no tensor-layout contract is
  proven. Already-published rows need no migration — the extra keys become
  unread JSON where they sit.
- The stamp was not merely unread, it was a **live veto over hardware we own**.
  `svdq-fp4` declared `sm_allowed=(120, 121)` + `engines=("nunchaku",)` — a
  kernel window and a wheel our native decoder has not needed since pgw#685 —
  so a B200/GB200 (sm_100) could not bind a flavor it serves, and no image
  without the nunchaku wheel could bind one at all. Correcting the constants
  was considered and rejected: a *correct* allow-list still vetoes the owner's
  own ladder rung.
- **pgw#1298's two deliberate survivors go with it.** `SVDQ_FP4_SMS` /
  `SVDQ_INT4_SMS` are deleted from `models/svdq.py` (their only consumers were
  this stamp and a tensorhub `WORKER_PARSED_CONSTANTS` peer pin th#2055
  removed), and `"nunchaku"` is dropped from
  `hub_policy.detect_worker_capabilities`' probe list — it was an ADMISSION
  TOKEN for a gate that no longer exists, and reporting it claimed a
  capability pgw#1298 deleted. The only SM window this stack still serves by is
  `svdq_native.SVDQ_NATIVE_FP4_SMS`.
- `tests/convert/test_placement_stamp_pgw1286.py` is **deleted, not skipped** —
  it transcribed the hub mirror table that no longer exists, and restoring it
  would re-derive the veto. `tests/convert/test_precision_class_stamp_pgw1300.py`
  replaces it at the same seam: it reads the declare request the fake hub
  actually receives and asserts `precision_class` is present and
  `sm_allowed`/`sm_min`/`engines` are not.
