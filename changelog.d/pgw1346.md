- **BREAKING — the typed SDK's types are named for what they are: a MODEL.**
  The package is `gen_worker.model`. A declaration is a `ModelSpec`, or a
  `GraphModelSpec` when it has graph classes. Codegen turns it into a `Model`
  subclass, a handler parameter is annotated with that subclass, and the value
  it receives is an instance of it — Python's own class/instance distinction,
  not two SDK types. The full old→new map, with no alias and no deprecation
  period (Paul, 2026-08-17): <!-- retired-spelling: the release note for a rename is the one place that must name what it renamed -->
  `gen_worker.family`→`gen_worker.model`, `Family`→`ModelSpec`, `GraphFamily`→`GraphModelSpec`, `FamilyBinding`/`FamilyInstance`→`Model`, `FamilyError`→`ModelError`, `FamilyRefusal`→`ModelRefusal`, `FamilyExport`→`ModelExport`, `declared_families`→`declared_model_specs`, `bind_families`→`bind_models`, `fake_families`→`fake_models`, `bound_families`→`bound_models`, `export_family`→`export_model`, `mint_family`→`mint_model`, `gen-worker family …`→`gen-worker model …`.
  Pin the old wheel, or bump and let mypy name every site.
  `scripts/lint_retired_sdk_spellings.py` is a required gate that refuses every
  retired spelling, with a selftest proving it can go red and that the
  surviving `family` WIRE vocabulary stays clean.
- **The words that did NOT move, deliberately.** `family_export_v1` is a
  versioned schema identifier — renaming it would re-key every committed export.
  `recipe_v1`'s `family` field, the `FAMILY` handle on a generated class, the
  `gen_worker.families` inference-defaults registry and `register_family` are
  the architecture-family vocabulary the hub and torchcg speak; they are not the
  SDK's types and they are unchanged. The `@endpoint(families={...})` kwarg is
  also unchanged in this release: it becomes `models=` in the same cut that
  deletes the `Slot`-typed `models=`, so the kwarg never carries two meanings.
- **The eager tier is PERMANENT, not a waiting room** (Paul, 2026-08-17). A
  model served by an external binary or a non-PyTorch runtime — vLLM,
  llama.cpp, a bespoke engine — has no graph to declare and therefore no
  obligation to declare one; it is a first-class `ModelSpec` citizen on the same
  declaration surface. pgw#1326's "LLM/VLM models are graph citizens with
  sessions" binds only where a traceable graph exists, and `spec.py` says so.
- Regenerating the catalog bindings under the new module path moved each
  model's `EXPORT_DIGEST` (a declaration's version IS its export digest, and the
  tuned schema's module path is part of the declaration): `sdxl` is
  `f1ba449a2197bfaae02ffa86c0a26ecb`, `flux1_dev` is
  `90b162d53cebd4da3afc06b003df7244`.
