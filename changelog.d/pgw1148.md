- **pgw#1148 (§1.32(d)): the SDK half of the flavor deletion — `#flavor` stops
  being a weight ADDRESS, and every picker that read one is gone.** Paul's
  ruling: *"the flavor system was an arbitrary-string sub-selector within a
  tag-group. It was too imprecise."* tensorhub landed the hub half in th#1803
  (`8d3bf511`): `repo_tags` is re-keyed to `(repo_id, tag, checkpoint_id)`, the
  `flavor` column is dropped, the ladder picks a CHECKPOINT and expresses it as
  a digest. This is the client side of that cut. **Deleted, not aliased**
  (pre-launch): there is no compatibility shim and no deprecation window.
- **The grammar SPLITS instead of dying.** `compile_cache.parse_cell_ref` reads
  the `#` tail — compile cells ARE `#`-shaped (`root/family-<f>:cells#ck1-…`) —
  so the tail survives in the parser exactly as tensorhub's own
  `release.ParseCanonicalRef` still parses it. `TensorhubRef.flavor` is now
  documented as THAT and only that, with the compile cache its one reader.
  **Zero bytes changed in `compile_cache.py`, `cell_key.py`, `aot_mint.py`,
  `aot_serve.py`, `trt_engine.py`, `fleet_cells.py`, `local_cells.py` or
  `mint_budget.py`** — the GPU/compile-cell homonym was never this ruling's
  subject, and a census that named every one of 531 `flavor` hits as
  model-ref, hub-wire, token-policy or compile-cell kept them apart.
- **A `#` on a WEIGHT ref is now a typed client-side refusal.**
  `refs.FlavorSelectorRemoved` + `refs.refuse_flavor_selector()`, raised at the
  site the author wrote — the binding constructor (`Hub`/`HF`/…) and the hub
  resolution fold — instead of being minted onto the wire and coming back as
  the hub's `flavor_selection_removed` / `binding_flavor_removed` **400**. The
  message names what to write instead: `Slot(layouts=…)` + `owner/repo[:tag]`,
  or `owner/repo@sha256:<hex>` for one exact checkpoint.
- **`Binding.flavor` and `Hub(flavor=)` are deleted, and nothing lost a live
  input.** th#1049 already made the hub 400 a deploy-time flavor pin, and
  th#1803 made the ladder's pick a DIGEST, so the field could only be filled by
  the LOCAL pickers below — themselves fed by `sibling_flavors`, which the hub
  no longer sends. `rebind_pick` loses its `flavor=` arm (a pick is a digest or
  it is nothing); `wire_ref` no longer folds a second selector;
  `execution_lane_{body_,}of_binding` take `storage_dtype` alone. The lane id
  keeps its two channels that carry EVIDENCE rather than an assertion: the
  hub-resolved execution lane and setup()'s pgw#1104 applied report — which
  already outranked the token at every call site.
- **The dead hub wire goes with it.** `resolve_repo` stops sending `?flavor=`
  and stops parsing `sibling_flavors` / `WorkerResolvedFlavor`; the hub serves
  neither since th#1803 (the route reads `tag`/`digest` and emits
  `tag_members`). With the rows gone, the pickers over them go too:
  `ladder.pick_family_fp8_flavor` / `maybe_rebind_family_fp8`,
  `provision._local_flavor_fold`, the `#flavor` suffix on the CAS tag-memory
  path, `hub_policy.svdq_flavor_kind` / `quant_flavor_kind`,
  `serve_fit._wanted`'s stored half, `execution_lanes.is_w8a8_flavor` /
  `mandatory_traced_lane_of`, the executor's `#flavor` th#1059 fallback, and
  the `flavor` row of the warm-contract key. `models/gguf_local.py` drops from
  330 lines to 66: its whole selection half addressed `owner/repo#gguf-<qtype>`
  and chose among sibling flavor rows — unreachable against the current hub —
  leaving the MARKER detection the loading layer actually uses.
- **`refs.flavor_token()` leaves the grammar module.** It was publish-body
  hygiene (`gguf:q4_k_m` → `gguf-q4_k_m`), not a ref concern; it now lives in
  `convert.hub` beside its only caller.
- **HF refs lose the `#flavor` tail and its CACHE-KEY FOLD.** HF never had a
  flavor axis — the tail was the orchestrator's per-flavor routing convention,
  and the fold gave two "flavors" of one repo two residency entries. File
  selection is `files=` / `allow_patterns`, carried beside the ref.
- **Measured and recorded rather than assumed:** the
  `precision_ladder_vectors.json` re-key th#1803 handed to this issue is a
  **no-op** — the "vendored byte-identical python-gen-worker copy" has not
  existed since pgw#515 (`4e7beb17`), which deleted the vectors, the test and
  the Python ladder walk together, and no Go test reads the file either. The
  reconciliation is a correction of that stale header, filed on tensorhub.
