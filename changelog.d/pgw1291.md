- **The component-dtype pin gate was silently OFF for four spellings, because 0 bits read as
  "agree".** `dtype_pins.dtype_bits` answered `0` for any spelling its table did not carry and
  `is_narrowing` treated `0` as "not narrower", so an unknown spelling did not make the gate refuse
  or complain — it made the gate AGREE, which is the exact shape of the pgw#1133 invisible-truncation
  bug this module exists to catch. Measured on the previous release: `int8`, `uint8`, `fp8_e4m3` and
  `fp8_e5m2` all scored 0 bits and all reported `is_narrowing(..., "fp32") is False`. `int8`/`uint8`
  are what a bitsandbytes tree carries; `fp8_e4m3`/`fp8_e5m2` is tensorlayout's canonical vocabulary.
  Four vocabularies meet in this module (`fp8:e4m3`, `fp8_e4m3`, `fp8-e4m3`, `F8_E4M3`), so
  `dtype_bits` now folds separators and case on both sides — one fact cannot be reachable through
  some spellings and not others.
- The durable half is the fence: every dtype token a producer in this repo can EMIT (read from
  `ingest._SAFETENSORS_DTYPE_NAMES` + `clone._KNOWN_DTYPES`, not restated) must have a width. The
  next vocabulary addition fails there instead of disarming a publish gate 45 minutes into a
  conversion on a rented pod.
