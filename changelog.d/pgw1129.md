- **pgw#1129 / th#1798: `Hello` carries the host driver version, so the fleet
  question is answerable from a SUCCESSFUL boot.** The hub only ever saw a
  driver version on the failure carrier (`HardwareUnsuitable`), and 0 of 42
  such rows on the standing stack carried one — so "no pod has ever hit a
  too-old driver" and "the create-time `allowedCudaVersions` filter silently
  stopped working" produced identical hub data. `WorkerResources.driver_version`
  (field 13, additive) is read from NVML rather than torch, because the whole
  point of the fact is that it stays readable when the CUDA runtime is not.
  tensorhub classifies it against NVIDIA's minimum-driver table and writes one
  `host_driver` census row per boot.
