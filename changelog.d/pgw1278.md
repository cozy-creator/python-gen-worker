- **BREAKING (pgw#1278, HARDCUT-CHECKLIST B3) — the worker speaks the
  COMPILED-GRAPH wire.** `/v1/worker/cells/*` is gone; the five routes are
  `/v1/worker/compiled-graphs/{resolve,publish-intent,publish-complete,receipt,revocations}`.
  The JSON body/answer key is `compiled_graph_key`, never `cell_key`. The
  receipt version is `compiled-graph-receipt-v1` (was `cell-receipt-v2`), and
  `RECEIPT_VERSION` is checked with `!=`, so a hub still signing the old
  version is REFUSED rather than misread. The broker action names are
  `compiled_graphs.*`, `gen_worker.cell_key` is now
  `gen_worker.compiled_graph_key`, and every `cell_*` activity event kind and
  refusal code is spelled `compiled_graph_*`. No alias, no dual-accept.

  This wheel requires a hub carrying tensorhub's half of the cut. Merging it
  changes nothing running: pods pin wheels, so the fleet meets the new
  vocabulary only when the hub lands and the endpoint images rebuild.

  `KEY_SCHEME` is unchanged (`cg-key-v1`) and no derivation moved: the shared
  `compiled_graph_key_vectors.json` corpus is byte-identical at
  `a274c570…`, so no published artifact changes address.

  **Not in this cut, and deliberately:** `ActivityUpdate` field 19 is still
  spelled `cell_key` in `proto/worker_scheduler.proto` — tensorhub owns that
  file and it moves in the proto lane. `gen_worker.activity` translates on one
  line at the seam. The `jit_cell`/`aot_cell` serving modes, the
  `cell_arm`/`cell_fetch`/`cell_hub_rtt`/`cell_verify` boot phases and the
  `FnUnavailable.reason` token `compile_cell_failed` are enumerated in the
  proto's own comments — a CLOSED vocabulary in that last case — and move
  with it.
