### The typed Family SDK (pgw#1332)

A **family** is now the one authoring contract for a model.
`@endpoint(families={"sdxl": Sdxl})` binds a handler parameter to a fully
resolved *instance* — graph, weights and the checkpoint's catalog-stamped tuned
values — and the generated family class is that parameter's type. Two
parameters of one family type are two checkpoints with independent tuning.

- `gen_worker.family` — the declaration vocabulary (`Family`, `GraphFamily`,
  `Runner`, `Bucket`, `Loop`, `Scheduler`, `TunedValues`), the
  declaration-time fake-tensor export (`family_export_v1`), the binding
  codegen, `FamilyInstance`, decode sessions for autoregressive families, and
  three interchangeable backings (eager / compiled / fake).
- `gen_worker.family.catalog` — the first-party catalog, with `Flux1Dev` and
  `Sdxl`. Import a family instead of diffusers.
- `gen-worker family export` / `gen-worker family generate` — the two build
  steps. Export needs torch but no GPU, no weights and no network; generate is
  a pure function of the exported document. A required CI gate proves the two
  committed halves still agree.
- Handlers never write `ctx.runner("denoiser")`: the name exists nowhere in
  handler source, buckets are exhaustive `Literal`s, and an incompatible
  re-mint breaks a *build*, not a pod.
- `Sdxl.fake()` runs any handler hubless and GPU-less, through its real code
  path, with shape-correct deterministic tensors.

**Breaking:** the free-standing `@family("sdxl")` class decorator is removed. A
family owns its tuned schema (`GraphFamily(tuned=...)`), and the registry
function `gen_worker.families.register_family(name, cls, kind=...)` is the
mechanism for a vocabulary with no family object. The registry, its
`(name, kind)` key and the exported JSON Schema are unchanged.
