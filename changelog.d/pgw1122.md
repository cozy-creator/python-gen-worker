- **pgw#1122: the cell receipt trust gate stopped asking a process that cannot answer who it is.** `receipts` decoded `cell_read_endpoint_id`/`cell_read_org_id` out of *this process's* worker JWT, but the gate is armed in the compute child, which holds no credential by construction (pgw#763 delta 1) — so both viewer ids were `""` on every split serving pod and every ORG-tier cell was refused `publisher_untrusted` after a successful resolve and materialize. Measured on three real pods (2026-08-11, gen-worker 0.104.0): the arm failure escaped setup as `worker_function_unavailable reason=compile_cell_failed`, the pods never served, were reaped `state_blocked_idle`, and replacements were bought. Identity now comes from one resolver, `gen_worker.worker_identity`, which reads this process's own credential when it has one and asks the control PARENT over the pgw#763 seam when it does not (`identity.viewer` — claims relayed, never the token), and refuses TYPED (`IdentityUnavailable`) when nobody can answer, so "the hub stamped no claims" and "nobody could be asked" stop sharing one value.
- **pgw#1122: a cell this pod adopted by its OWN derived key no longer takes the function down when it will not arm.** §4.27 boot-adopt built the same `_ArmOrder` shape a hub Plan dispatch builds, so a typed arm refusal was terminal (pgw#904) even though nothing had ordered it. It now emits a `boot_adopt` activity event with `phase=arm_refused` naming the refusing gate, drops the order and runs the ordinary fleet policy — the boot every pod did before boot-adopt existed. A hub-ordered arm stays terminal, and a mandatory (w8a8/w4a4) lane still fails closed.
- **pgw#1122: the defect CLASS is fenced.** `scripts/lint_credential_identity.py` (fast gates) requires every worker-credential read in `src/gen_worker` to carry a classification in `scripts/credential_identity_allowlist.txt` — and there is deliberately no `IDENTITY` classification, because a site that needs to know which endpoint or org this pod serves calls `worker_identity.viewer()`. This is the second instance of the same seam bug (pgw#1108 was the first, one gate earlier); the third has no label to write down.
