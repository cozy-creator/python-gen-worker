- **pgw#1327: the derived `cg-key-v1` set ships as DATA — a fresh pod boots with
  zero `torch.export` calls.** `boot_key.derive` learned a boot's key set by
  running structure-only `torch.export` traces in child processes, on every
  fresh pod, and said so itself: *"< 60 s, every time, ~99 % of it the traces."*
  Every input to those traces is code the mint lane already ran, so a pod that
  will never compile anything was paying a minute of exporter — and holding a
  hard dependency on torch, diffusers and the endpoint's model code — to
  recompute a pure function of its own source.

  The output is now a versioned document, `cg-keyset-v1`
  (`gen_worker.keyset`): per declared graph class, TCG's machine-independent
  `class_hash` plus its metadata (graph-class handle, ingress digest, target),
  addressed by the closure digest that says which code produced it. A pod folds
  those hashes with its own freshly-stated `sm` and toolchain, which is why one
  document serves every SKU and why a toolchain upgrade still moves every key on
  the very next boot. **No folded key is ever shipped or stored.**

  `boot_adopt` reads the document (image root `/app/.tensorhub/`, or
  `GEN_WORKER_CG_KEYSET`, then this machine's own cache) and takes the tracer as
  an INJECTED fallback — it no longer imports `boot_key`, and
  `scripts/lint_serve_keyset_closure.py` fails the build if the serve-boot key
  path can reach one. Proven both ways: `tests/test_cgkey_as_data_pgw1327.py`
  derives a real key set through the trace children, ships it, and re-boots with
  `torch.export` and `subprocess.Popen` booby-trapped — the same keys, key for
  key, with neither sentinel touched.

- **pgw#1327: drift fails safe, by address rather than by comparison.** A pod
  whose closure digest is not in any document has no key set at all — it never
  reads "the nearest" closure — and with no deriver injected
  (`GEN_WORKER_ADOPT_ONLY=1`, and pgw#1328's serve role structurally) that is a
  typed `keyset_absent` refusal that states no key and adopts nothing. A
  document that is malformed or a version this worker does not read refuses as
  `keyset_invalid` rather than degrading to a miss, because a broken shipped key
  set is a mint-lane defect and reading past it is how a whole release traces
  forever with the artifact sitting beside it. Identifiers are parsed into
  validated types at the boundary (`ClassHash`, `IngressDigest`, `ClosureDigest`,
  `CompiledGraphKey`); the key shape is admitted through TCG's own grammar
  rather than a second regex.

- **pgw#1327: the boot-memo honesty gate was addressing a closure nothing ever
  wrote.** `mint_supervisor.rule_on_boot_memo` computed its closure digest
  WITHOUT `modules`, while every derivation passes it — so the comparison that
  makes a cached (and now shipped) class hash safe to fold read an absent row and
  returned `""` on every pod. Same defect class as the zero-caller one pgw#1271
  found, one argument deeper. Fixed, and `tests/test_wired_gates_pgw1271.py` now
  passes the task's own `modules` at both ends.

- **pgw#1327: `boot_key` / `boot_trace_child` are mint-lane tooling.** They still
  own the derivation — an ordinary Python serving pod that misses and mints runs
  it once and records the closure (§4.28: minting is a side effect of serving) —
  and `scripts/emit_cg_keyset.py` stages that document for baking beside
  `endpoint.lock`, either from a pod's cache or by running the derivation
  deliberately. **Flagged, and NOT decided here: this moves §4.29's stated
  mechanism** (*"the worker itself is the one that figures this out, by tracing
  the graphs"*) **to mint time. The substance of §4.29 is unchanged — pull by
  key, one artifact or MISS, admission verifies against the key — but the
  mechanism amendment is Paul's to make. §4.28/§4.30 are untouched: no forge, no
  mint requests, no compile fleet.**
