- **The four retired env NAMES leave `_OWNED_NON_SETTINGS`, and the predicate that held them was
  wrong rather than merely unowned.** pgw#1270 deleted the read sites for
  `GEN_WORKER_AOT_RUN_IMPL_SPLIT_OFF`, `GEN_WORKER_AOT_HOST_COMPILE_JOBS` and both
  `GEN_WORKER_MINT_RESUME_*` and then held the NAMES on *"a fresh measured count of zero"*,
  because *"dropping a declared name makes a pod that declares it fail config load."* Nobody was
  ever going to run that census — but the interesting half is that it would not have mattered.
  **`UnknownSettingError` is raised only from `_normalize_key(strict=True)`, whose only callers
  are the FILE sources** (`.env`, yaml, `/run/secrets`). The process environment never reaches
  it: `_load_env` indexes `_ENV_TO_FIELD` and never asks about a name it does not know, and
  `unrecognised_owned_env` REPORTS owned-namespace residue at boot instead of refusing it — its
  docstring says why, verbatim. And the hub delivers a release's declared env ONLY as container
  process env (RunPod `CreatePodRequest.Env`, Vast `CreateInstanceRequest.Env`, k8s inline
  `corev1.EnvVar`, local `docker run -e`); it writes no config FILE into a worker container. So a
  pod still declaring one of these boots green and NAMES the name at boot, which is what retiring
  a name is supposed to do. The census was never the gate, and pgw#929's now-unsatisfiable
  version of the same sentence (*"after the five live declarations are removed and the split is
  proved"* — pgw#1270 deleted the split) needed correcting, not satisfying.

- **`destination.repo` dies — and it was hiding a live defect, not just residue.** pgw#1227 named
  the key *"the shape of a retired key still being accepted"* in `executor._producer_destination_repo`
  and routed it to another repo's lane. The reader was here, and there were TWO of them.
  `convert.publish.publish_flavors` read `ctx.destination["repo"]` **and nothing else**, while
  its sibling `destination_release` — in the same module, on the same struct — refuses with
  *"invoke with destination={ref, release}"*. So the exact invoke the refusal asks for was
  answered with `destination_repo is required`: the two halves of one reserved struct disagreed
  about its key, and the half a producer hits first told it to use the spelling the other half
  cannot read. Both now go through `destination_ref()`, which reads `ref`, strips
  tag/flavor/checkpoint selectors, and shares one vocabulary with the executor.

- **The chunk-manifest parser stops accepting keys the hub has never emitted.**
  `models.hub_client.parse_chunk_list` mirrored `digest`/`sha256` and `len`/`length`, in a module
  that states the opposite rule verbatim 100 lines up (*"an integrity check with no digest is a
  REFUSAL, never a skip… reinstating the mirror arm re-opens the vacuous guard this whole program
  exists to close"*). Read off the hub's serializer: `catalog.SnapshotChunk` is `{digest, len}`
  and has been since it was born at th#1303 — `sha256`/`length` are not retired spellings on this
  route, they never existed on it. The `length` arm is the dangerous polarity: it made a chunk of
  unknown length read as length 0. The gRPC `ChunkRef` (`sha256`/`url`/`len`) is a different
  wire read off the typed proto in `models.store` and never reaches this parser, which is what
  the docstring now says instead of implying the two vocabularies should be merged.

- **`read_audio` gets the resampler it advertises.** `io.read_audio` caught `ImportError` from
  `scipy.signal.resample_poly` and fell back to `np.interp`, with a docstring promising polyphase
  *"when scipy is available"*. **scipy was declared nowhere** — not in `dependencies`, not in an
  extra, not in dev — so the import ALWAYS raised and every tenant calling
  `read_audio(target_sample_rate=…)` got naive linear resampling. A fallback that is the only
  path is not a fallback. scipy joins the `audio` extra beside soundfile/numpy and the arm is
  gone, so the advertised resampler is the one that runs.
