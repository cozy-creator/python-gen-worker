- **th#1871 P1's worker half — the serve POSTURE is typed and rides
  `JobMetrics` (pgw#1225).** DESIGN-RULINGS §1.36 stage 2: *"a benchmark
  measured through a silent degradation is not a benchmark."* The deciding
  specimen is ie#707 — a family served on `sdpa` because flash-attn was absent
  from its image while its lane declared flash, and every number taken from those
  runs was filed as a measurement OF the flash lane. tensorhub now keys
  `endpoint_measurements` on a posture digest (th#1871 P2, `4f57e6e6`), and until
  this change every `source='serve'` row got the UNREPORTED posture: the hub's
  reducer deliberately refuses to parse the prose the worker already emits into
  `worker_activity_events.detail`, because parsing prose to recover structure is
  the defect that table exists to end. So this is a change of REPRESENTATION,
  not of instrumentation — every field was already known, and already said, in
  words, on a channel no decision reads.

  New wire message `MeasuredPosture` on `JobMetrics.posture` (field 24),
  mirroring Go's `measurement.Posture` field-for-field so the digest needs no
  translation layer. It carries the resolved lane, the attention backend
  ENGAGED and the one WANTED, the compile state applied and declared, the
  residency rung, the ORDERED list of levers reached for, per-component
  applied-vs-bound quant, and a typed VRAM shortfall (`needed N, had M`). Not
  named `ServePosture`: that message already exists and is the hub→worker
  operator eager-only command (§4.32).

- **New public reporter: `gen_worker.report_attention_backend(component,
  backend, *, wanted=...)`.** `report_applied_attention` reports SPARSITY
  (`dense` / `sparse-k<N>`) and raises on `"sdpa"` — correctly, because a kernel
  is not a sparsity budget, and 23 of 29 families consequently reported nothing
  at all. The kernel is a second axis and gets a second reporter. Ecosystem
  spellings (`flash_attention_2`, `FlashAttention-3`, `torch_sdpa`, `math`) are
  normalized rather than refused; a token tensorhub does not share still raises,
  because that is a fourth vocabulary and the reporter is the last place to stop
  one. `AppliedAttention.mode` is now optional — a backend-only report says
  nothing about sparsity and must not read as a claim of dense.

- **The declared compile axis comes off BOTH hub statements.** `compile_state_wanted`
  reads the instructed lane's `+compiled` suffix, and falls back to the
  `required_compile` fence — because `RunJob.lane` is empty whenever the lane
  rides `HelloAck`'s `ModelResolution` instead of a per-request override
  (`scheduler_dispatch.go:1037`: `"" = policy`), and on that path the fence is
  the only thing that states the axis. Unstated stays EMPTY rather than
  defaulting to eager: a mismatch needs a stated expectation to violate, and
  inventing one would report every policy-dispatched request as a clean
  compiled-vs-eager agreement.

- **The PROACTIVE descent is reported.** `memory.place_pipeline` keeps the fit
  numbers its own decision was made on, and the executor records the posture for
  EVERY placement rather than only the OOM-demoted one. A pipeline that
  `select_auto_mode` put on the offload ladder never OOMs, so it reported
  nothing, served 2.5-4x slow, and its numbers were filed as a resident run —
  the largest silent degradation th#1871's census found.

- **The collapsed rungs get names.** `model_offload`, `group_offload` and
  `sequential` stop sharing the wire token `offload` (their prices differ by
  60%), and `vae_slicing` and `attention_fallback` get a wire representation at
  all. A degraded run now also logs one derived summary line — §1.36's amendment
  asks the worker to complain loudly, and the line is derived from the typed
  record so the two cannot disagree.

- **Cross-repo fence:** `tests/testdata/posture_wire_vectors.json` +
  `scripts/posture-vector-drift.sh`, vendored byte-identically in tensorhub. The
  DIGEST has exactly one implementation and it is the hub's — the worker pins
  the digests as opaque data and never derives them, because a second
  canonicalization of one object is two implementations free to disagree while
  both suites stay green (pgw#1188's topology divergence, one contract over).
  The ledger's `identity_rules` state which pairs of postures are one
  measurement; those are §1.36 decisions, not implementation details.
