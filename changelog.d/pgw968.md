- **pgw#968: lanes stop serialising on one mutable `CHANGELOG.md`.** Every
  concurrent lane appended to the same file, so a CHANGELOG-only conflict on
  `dev` was near-certain for any PR that sat through a single sibling merge —
  one lane rebased three times in a night, each time on a different sibling
  merge, each time on the same one hunk, and got in on the third largely by
  timing luck. Entries now go to `changelog.d/<issue>.md`, a path no sibling
  touches, and `scripts/assemble_changelog.py --version X.Y.Z` collapses them
  into a release section at cut time, ordered by issue number so the result
  never depends on filesystem order. `CHANGELOG.md` becomes append-only history
  that lanes do not edit. Nothing automated ever read it — `pyproject.toml`'s
  long description is `README.md`, and neither `ci.yml` nor `publish.yml`
  mentions it — so the change is free.

- **pgw#968 / gw#666: `test_nested_stages_are_charged_exclusively` asserted a
  literal millisecond band over a `sleep`.** `15 <= upload <= 35` around a
  `sleep(0.02)` was red at box load 90 and green at load 17 with no code change:
  the upper bound was an assertion about scheduler latency, which no load
  guarantees (measured 260 ms under single-core oversubscription). The bounds
  are now derived from the sleeps themselves — the child's floor is a ceiling on
  an exclusively-charged parent, parent+child fill the handler window, and
  `resid.overlap` must be absent — which is the actual nesting claim and holds
  at any load. Verified red against injected inclusive charging.
