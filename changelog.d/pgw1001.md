### Fixed

- **A bucket-bearing cell can be adopted by the runtime that minted it
  (pgw#1001).** Three defects, each of which alone made that impossible, all
  found on the local rig in ~20 s a cycle once pgw#999 made the refusal say its
  own name. sdxl mints `w8a8-lora64`; this is that lane's LoRA half.
  1. `arm_aot` resolved its lifted target from `meta["targets"]`/`meta["module"]`,
     which a packed multi-entry cell does not carry — the targets are recorded
     PER ENTRY. `module_name` came out `""`, the lifted-binding install was
     silently skipped, and `aot_serve.enable` then refused the artifact it had
     just been handed with `lifted_inputs_unbindable`.
  2. With that fixed, the naive `targets[0]` picked `decoder` (entry-name
     order). `lora_lifted.branch_targets` is the one authority on which module
     is the denoiser, and it is what chooses now.
  3. **The invariant: arming a bucket must not alter the semantics of calls
     that do not use the bucket.** `install_lifted_lora_forward` replaces
     `model.forward` wholesale, so a plain call that worked the instant before
     the install raised `ValidationError: the lifted LoRA argument 'lora_a' is
     missing` the instant after it. That is a SERVING break — a branchless
     request falling back to eager on an armed pod hits it in production — and
     it surfaced as `numerics_refused` only because the numerics gate is the
     thing that probes the branchless axis (pgw#790's adapter fork). The lifted
     forward now takes the plain branch when BOTH adapter operands are absent
     at the denoiser's own arity; one operand alone is still a caller error,
     and the fallthrough never fires while a graph is being CAPTURED, because
     an adapter class traced without its operands would silently capture the
     branchless graph under the adapter arm's name.

  With all three fixed the `micro-lora` vehicle mints 5 entries, publishes,
  adopts, arms, passes the numerics gate and reaches parity 7.15e-07 in 24.9 s.

- **The micro family's loader is STRICT (pgw#999 follow-up).** Under
  `strict=False` a checkpoint written with a different prefix loaded ZERO
  tensors and left the module randomly initialized — silently. Renaming the
  family's denoiser did exactly that, two processes then held two different
  random modules, and the rig read it as a 0.151 numerics divergence and spent
  a session accusing the numerics gate, which was right all along. The loader
  now refuses by name, quoting the prefixes the tree actually has, and the
  generated tree carries a `LAYOUT_VERSION` so a rename invalidates the cache
  instead of leaving bytes no loader can read.

### Changed

- `micro-lora`: a `lora_bucket=64` rig vehicle for the pgw#997 micro family —
  the branch-bearing graph, which is the axis sdxl's refused cell differs on.
  The rig's adopt child now constructs the same `CompileCell` the mint was
  keyed on (a hardcoded `lora_bucket=0` made a bucket-bearing vehicle reject
  its own cell with `lane_mismatch` before arming), takes its eager reference
  from a pristine second instance, and reports RED when the arm refuses —
  which it previously did not, the same defect class one layer out.
