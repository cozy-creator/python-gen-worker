- **pgw#1279 ⇄ th#1987 (HARDCUT A9, and the pgw leg of A8): the ref grammar is
  re-keyed onto releases — `:tag` DIES, `@<release>` arrives.** `models/refs.py`
  now speaks `owner/repo[@<release>|@sha256:<hex>|@blake3:<hex>][#fragment]`,
  matching `release.ParseCanonicalRef` decision for decision. `DEFAULT_REF_TAG`
  and the `:prod` elision are DELETED: there is no default and nothing is
  elided, so a bare `owner/repo` names a repo and no artifact inside it —
  exactly what the hub's `ResolveCheckpointSelector` answers with the terminal
  `release_not_found`. A ref carrying `:` raises the typed `RetiredTagRef`
  naming the remedy, which is the client-side twin of the hub's own refusal:
  the alternative is a `repo:prod` that parses as a repo nobody has and
  resolves to nothing 45 minutes into a mint.
- **pgw#1279: th#1387's injectivity hole is CLOSED, not carried over.** Owner,
  repo, release and digest all refuse a ref-grammar separator (`/@:#`), so
  `owner/repo/extra` and `owner/repo@a@b` are refusals rather than values whose
  normal form re-parses to something else. `tests/test_ref_and_manifest_fuzz_pgw867.py`
  drops its `_known_grammar_hole_th1387` escape hatch and asserts the invariant
  outright.
- **pgw#1279: the release rides the REF, and the side-channel `tag` field is
  gone from every seam.** `Hub(ref, release=)` / `ModelRef.release` replace
  `tag=`; `discovery` emits the normal-form ref (`owner/repo@<release>`) into
  the endpoint manifest instead of a separate `tag` key; the provider index,
  the CAS offline ref map (`cas/refs/<owner>/<repo>/<release>`) and
  `hub_client`'s `?release=` query follow. The hub reads the release out of the
  ref with `ParseCanonicalRef`, so no hub change is needed for the ref to
  resolve.
- **pgw#1279: the shared conformance corpus is re-keyed in both vendored
  copies.** `ref_grammar_vectors.json` carries `release` in place of `tag`, adds
  release-addressed vectors, and turns every `:tag` spelling into a REFUSAL
  vector; the fragment boundary at 96/97 and every digest vector survive
  unchanged. Combined `@release@digest` vectors are deliberately absent from the
  shared corpus: the canonical form drops the release when a digest is present,
  so such a vector cannot be a round-trip fixed point — the digest-wins rule is
  asserted separately on both sides.
- **pgw#1279: `publish_v2(release=...)` is REQUIRED — no default, so every call
  site states one.** `tags=`/`head=` are deleted with the axis they addressed.
  The conversion producer and the clone take the release from the invoke's
  `destination.release` (`convert.destination_release`), `ctx.save_checkpoint`
  takes it from the execution hints the executor now carries beside
  `destination_repo`, and the self-mint compiled-graph publish states the ONE
  legal exemption by name (`COMPILED_GRAPH_NO_RELEASE`) because the hub answers
  `release_forbidden` to a cell publish that names a release. A publish with no
  release refuses at the call site with `HubReleaseRequiredError` rather than
  after the transfer.
- **pgw#1279: `scripts/lint_repo_ref_pins.py` — a fence over src + tests with
  NO allowlist.** A `:tag`-shaped repo-ref literal is refused wherever it is
  typed; the two places one legitimately survives are recognised by PROOF OF
  REFUSAL (a corpus vector carrying `"error": true`, or a line carrying
  `# refused:`), never by path — a path allowlist would let a real pin hide
  behind a filename. Wired into the required `fast gates` job with its own
  `--selftest`, and RED on `origin/master` naming 131 pins.
