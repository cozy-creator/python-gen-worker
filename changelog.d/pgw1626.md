- **pgw#1626: `ctx.load` re-ties tied weights before it asserts, so T5-bearing pipelines load again.** The meta skeleton is built from configs alone, so `post_init()` — and with it `tie_weights()` — never ran, leaving a tied pair as two independent meta tensors. A correct `T5EncoderModel` checkpoint stores `shared.weight` and not `encoder.embed_tokens.weight`, so the alias was never filled and `meta_survivors(remove_duplicate=False)` reported it as missing: every T5-bearing pipeline on the streaming loader (StableAudio, every FLUX.1 `text_encoder_2`) failed 100% of its invokes with a `NameMismatch` that blamed the checkpoint for a defect in the loader. The engine now calls `skeleton.retie()` after the last container and before the survivor check. The assertion is NOT weakened — `_tied_weights_keys` is no exemption, so a genuinely absent tensor under a tied name is still refused — and the refusal now names the module class, says the tensors were never filled, and says whether a tie was expected instead of accusing the artifact.
