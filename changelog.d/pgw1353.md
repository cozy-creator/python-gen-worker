- **pgw#1353: the derived `cg-key-v1` set survives the pod that paid for it —
  a cold sdxl boot stops spending 805 s on `torch.export`.** Measured on four
  independent fleet pods: `keys_from=traced`, 778-833 s per cold boot, 36 graph
  classes, every time. pgw#1327 built the document that deletes that cost and
  gave a fleet pod two ways to read one, and neither reaches it. The BAKED image
  root cannot be produced at all — the closure digest binds the checkpoint ref,
  and for an sdxl-shaped `Slot(selected_by=...)` that ref is a deploy-time hub
  pick the image build cannot state. And the pod's own cache is
  `tensorhub_cache_dir or tempfile.gettempdir()`, which the hub deliberately
  leaves unset (th#850) — so **the document was being written to `/tmp` and
  thrown away with the pod**, which is why `compiled_graph_store` sat at zero
  rows while every pod re-derived the same 36 classes.

  The document now goes on the root the platform ALREADY places for this exact
  class of artifact. th#1813 has the hub set `GEN_WORKER_LOCAL_CELLS_DIR` on
  every create, pointing at the most durable storage the provider can back: the
  endpoint's NETWORK volume when one is attached — shared by every pod of that
  endpoint — and the pod's volume disk otherwise. `keyset.store` reads and
  writes `$GEN_WORKER_LOCAL_CELLS_DIR/keysets/`, namespaced so it cannot collide
  with the `aot-cells/` tier beside it. Search order is **shipped → durable →
  this pod's cache**, and `writable_roots()` is the single ordering that
  `lookup`, `class_hashes`, `write_closure` and `invalidate` all walk, so a root
  that can be read is by construction one that can be written and invalidated.

  A durable hit reports its own `KeySource.DURABLE` (`keys_from=durable` on the
  `boot_adopt` event) rather than borrowing `memo`: on a fleet pod the pod-local
  cache is `/tmp` and a fresh pod's is empty, so `keys_from=memo` is very nearly
  a contradiction there, and the one number this issue moves — how many pods
  still pay the 805 s — has to be a query rather than an inference.

  **It is an optimization, never a gate.** No root placed, an unwritable volume,
  or a document for another closure each fall through to the deriver and boot
  exactly as before; a CORRUPT document still refuses loudly under
  `keyset_invalid` (pgw#1327's rule) instead of degrading to a silent re-trace.
  A row `assert_honest` proves dishonest is now dropped from every writable root
  — leaving it on a shared volume would re-poison every pod of the endpoint. The
  atomic write took a random temp suffix: the fixed `cg-keyset-v1.tmp` it
  replaces is a name two pods of one endpoint would write to simultaneously.

  Also fixed: `scripts/emit_cg_keyset.py --derive` had been unrunnable since
  pgw#1333 — it built `MintSlot(ref=None, path=path)` against a struct with a
  required `ref` and a required `facts`, and raised `TypeError` before tracing
  anything. It now takes `--slot NAME=PATH` (where the checkpoint TREE is, for
  the structure-only build's configs) and `--slot-ref NAME=REF` (WHICH
  checkpoint, which rides the closure digest), and refuses a slot carrying only
  one of the two rather than deriving a document addressed at a closure no pod
  looks up.
