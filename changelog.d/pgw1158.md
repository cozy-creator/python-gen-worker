- **pgw#1158: a fork's ARMS must agree with the classes that cover them, and a closed arm must
  say what closes it.** Found empirically by the endpoint-adaptation lane, which ran a severance
  experiment against the declaration construction surface while writing sd15's and sd2's
  declarations. The SDK caught the copy-paste (sd15's 14-class set on sd2 → *"graph class #0 sits
  on UNSERVED arm cfg=True"*) and silently ACCEPTED two subtler errors.

  **A served arm no class covers.** Every existing check reads CLASS → ARM, so the reverse
  direction was never asked: a `Fork` claiming both arms served while its classes cover one was
  accepted. The declaration claims to serve the arm, the mint traces nothing for it, and the
  first request on it finds a graph that was never exported. Now refused by name, with both ways
  out in the message (declare the class, or move the arm to `unserved` with a `reason`). Only
  asked of a class-declaring family — a shapes-declaring one has nothing that could cover an arm,
  and forks are legal there.

  **An unserved arm with no `reason`.** This was a rule the field's own docstring asserted —
  *"required whenever `unserved` is non-empty"* — staged as phase 2 because "every fleet
  declaration predates this field". The reminder test even said it "will need deleting when that
  lands — which is the point". Until then the field read as a guarantee to every endpoint author
  and enforced nothing. Phase 2 lands here: `None` no longer means "not answered yet", because
  that state is now unconstructible. A served-only fork still needs no reason — it closes nothing.

  Both are DECLARATION-time refusals, so they cost nothing at serve time. The in-repo declarations
  they correctly rejected are annotated rather than exempted, including LTX's draft (whose three
  forks carried prose `why=` and no machine `reason=` — precisely the prose-doing-a-machine's-job
  failure the pair was invented for). The severance experiment is kept as a test row and run
  against these guards: a validator that never fires is the defect being fixed.
