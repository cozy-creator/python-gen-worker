- **`RunJob.output_mode` is now `RunJob.media_bytes`, enum `OutputMode` -> `MediaBytes`
  (`MEDIA_BYTES_UNSPECIFIED|URL|INLINE`)** — the field carries ONE thing, the client's
  `Prefer: bytes=inline|url` media-delivery preference, and the old name collided with two
  unrelated questions: this module's own `EndpointSpec.output_mode` (the function's output
  cardinality, still spelled that way until pgw#1320) and the hub's SSE terminal-payload budget
  signal (renamed to `delivery` by th#2079). Landed in lockstep with tensorhub th#2082.
  **The wire is unchanged**: field number 9 and enum numbers 0/1/2 are identical, so this is a
  source-level rename and a peer on an older build still parses every dispatch.
- The one consumer, `executor._legacy_order`, is now fenced on the value the worker
  **RECEIVED** rather than on the field being set (`tests/test_media_bytes_th2082.py`). If that
  read is ever lost, nothing raises — every `Prefer: bytes=inline` request silently degrades to
  URL delivery and uploads bytes the client asked to have handed back. The three arms run a real
  worker over a real gRPC socket against a real upload sink and read the decision from both the
  sink and the handler's own Asset; the fourth pins field 9's wire bytes, which is the half a
  typed assertion structurally cannot see.
