- **pgw#1642 / tcg#80: the compiled-graph mint no longer builds a SECOND full
  constant set on the first call, and the compile policy is now part of the
  artifact key.** Vendored torchcg moves from
  `aot_inductor.use_runtime_constant_folding=True` to
  `always_keep_tensor_constants=True`. Both flags take torch's identical
  bindable-constant branch (`GraphLowering.get_attr`), so the constant table an
  artifact declares is unchanged — but the runtime-folding split additionally
  ran a const-fold subgraph on the first compiled call and materialized a folded
  copy of every folded weight by a direct `cudaMalloc`, outside the PyTorch
  caching allocator. On an sdxl UNet that was ~4.8 GiB of first-call transient on
  top of the eager weights the artifact already points at by raw pointer, which
  is why an 8 GiB card could not serve it. Nothing is inlined under the new
  policy either, so no checkpoint value is compiled into the code and pgw#1097's
  fence needs no exemption. `models/lora_fold.py`'s stale-folded-constant hazard
  disappears with it (the `rebind` gate stays, fail-closed, for pgw#1571).
  Artifact keys move — `cg-key-v1` → `cg-key-v2`, `cg-env-v2` → `cg-env-v3` —
  because the compile options now reach both derivations; previously a fold-on
  and a fold-off mint of one graph shared an address and the second publish died
  on `FileExistsError`. Existing artifacts re-key and re-mint; nothing is
  silently mismatched.
