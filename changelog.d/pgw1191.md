- **pgw#1191: the publish gate stops accepting evidence from a run that never built the tree — pgw#795's v0.78.0 hole, through a different door.** `publish.yml` proves a tag by matching its tree against a green `ci.yml` run, keyed on the run's `head_sha`. But `ci.yml` checks out with `actions/checkout@v4` and no `ref:`, so a **`pull_request` run builds `refs/pull/<n>/merge`** — the PR head merged with whatever `master` is at that moment — **while still recording the PR branch head as `head_sha`**. Compose the two and the gate certifies a tree no run ever executed, whenever master moves under a cut. That is the normal case: master moved four times during the 0.113.0 cut, whose PR run went green naming the exact commit that was tagged. The check was never relaxed — it was **weaker than it read**, which is worse, because every signal was green.
- **Only a checkout that IS the commit it names can prove it**, so `workflow_dispatch` and `push` are admissible and everything else is refused **deny-by-default** — a new event type has to be classified before it can ship a release. The matcher moves out of inline shell into `scripts/assert_ci_proof.py` so it can be tested, and the refusal is **typed**: `only_pull_request_proof` (your tree is fine, your evidence is the wrong kind — dispatch CI and re-run publish) is a different verdict from `no_run_carries_tree` (this content has never been tested anywhere), because they need different actions and a releaser reading a red publish should not have to guess.
- **Proven in both directions**, since the failure mode of a stricter gate is one that blocks every release and looks like rigour: a `pull_request` run carrying the exact tree is REFUSED, and a `workflow_dispatch`/`push` run on the same commit still PASSES — including when both exist for one commit, in either order. RED-proven by restoring the event-agnostic behaviour: 4 rows fail, the over-refusal rows stay green. A fence row fails if `publish.yml` ever inlines the shell matcher again. Trees-not-commit-shas is unchanged and asserted: a squash or cherry-pick with identical content still proves.
- **No release needs re-auditing. 0.113.0 is unaffected** — it was cut from a pinned base whose ancestors were each individually CI-green, the merge tree CI actually executed was a superset of the tagged tree, and the published wheel was verified by downloading and opening it.
