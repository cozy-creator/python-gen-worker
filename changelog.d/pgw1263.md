- **The snapshot headroom gate sizes the copy it was gating, and always runs.** `_publish_snapshot`
  writes a second full copy of every manifest file next to the CAS objects it was built from, so a
  resident snapshot costs roughly twice its size on disk — and the gate ahead of it sized only the
  objects still to FETCH. It was also spelled `if missing and required > free`, so on a warm pod, a
  volume fill or a retry — every object already resident, the publish the sole writer — the
  comparison never ran at all. Such a pod passed the gate and then hit ENOSPC part-way through
  materializing, leaving a partial tree. The gate now sizes fetch + publish + reserve, always
  evaluates, and the refusal names both halves so an operator can tell a download that will not fit
  from a publish that will not fit.
